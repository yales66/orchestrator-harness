# ADR 0024：编排手册分段注入，每段都在单个钩子的上限之内

## 状态

已采纳，自 2026 年 11 月 7 日起生效。本决策修订 [ADR 0001](0001-orchestration-rules-reach-only-the-main-thread.md) 的送达细节：`hooks/orchestrator-playbook-session-start.sh` 不再把整份手册作为一个 `additionalContext` 注入，而是按段各注册一次，每次只注入一段；ADR 0001 其余内容不变，手册仍是这些规则的唯一一份，也仍只送达主线程。本决策取代 [ADR 0008](0008-subagent-effort-per-kind-of-dispatch.md) 后果一节里的一条：手册一到 10,000 字符 `scripts/check-parity.sh` 就报错，所以要在英文手册里加路由文字就得删掉别的内容。

## 背景

单个钩子在会话启动事件里输出的 `additionalContext` 超过 10,000 字符时，Claude Code 把它存成文件，只给模型 2KB 预览。字符数按 JavaScript 字符串长度算，即 UTF-16 码元。ADR 0008 记录英文手册为 9,993 字符，刚好在上限以内，`check-parity.sh` 在手册超过这个长度时报错。

2026 年 11 月同步进来的规则让英文手册变成 22,329 字符，中文手册 7,815 字符。英文手册整份注入的话，主线程只能拿到预览。

2026 年 11 月 7 日，作者在 Claude Code 2.1.319 上实测这个上限是按会话启动的全部输出算，还是按每个钩子分别算。同一事件注册两个钩子，各输出 9,500 字符，两份都完整送达；一个钩子输出 12,000 字符，只送达预览。所以上限按单个钩子算。

同一事件注册的几个钩子并行运行，模型看到各自输出的顺序是各钩子结束的先后。一次实测里四段按 4、1、3、2 的顺序到达。

## 决策

钩子接受 `--part N`。带这个参数时，钩子把手册切成每段不超过 9,500 个 UTF-16 码元的若干段，只输出第 N 段；段号超出总段数时什么都不输出。切分先按 `## ` 节标题；单节放不下的按空行切，再放不下按行切，单行仍放不下按字符硬切，不劈开代理对。手册一段就放得下时原样输出。需要多段时，每段以 `[orchestrator playbook, part i of n]` 一行起头，去掉这一行后按段号拼接，与手册逐字节相等。不带 `--part` 时钩子仍输出整个文件。

第 N 段输出前先等 (N-1) × 0.3 秒，让各段按段号先后结束。等待时长由 `PLAYBOOK_PART_DELAY` 设定，缺省 0.3。改动之后的两次实测里各段都按 1、2、3、4 到达。

两份副本的 `settings.example.json` 都在会话启动事件上把这个钩子注册四次，分别带 `--part 1` 到 `--part 4`。在本分支上，英文手册切成四段，含标签行分别为 2,327、9,260、9,338 与 1,552 字符。中文手册一段就放得下，第 2 到第 4 段的注册项什么都不输出。

`scripts/check-parity.sh` 不再按手册长度报错。它对每份副本逐个运行已注册的段号，有任何一段超过 9,500 字符，或者手册需要的段数多于设置注册的段数时报错，因为多出的那一段永远到不了主线程。

## 后果

手册可以超过 10,000 字符而不被截成预览；手册长到注册的段数不够时，一致性检查会指出该怎么修：在设置里再注册一个 `--part`。

9,500 的上限在实测上限之下留了 500 字符余量；这个余量是作者定的，不是实测得出的需要。单个钩子的上限只在一个 Claude Code 版本上、在一天里测过，之后的版本可能改变计数方式。

段的先后靠时间差保证。0.3 秒的间隔是作者定的，两次实测按序到达，不足以证明总能按序；机器负载很高时各段仍可能乱序到达。每段的标签行写有段号与总段数，乱序时模型也能认出顺序。

只复制了新钩子、设置文件里仍是那一条不带 `--part` 的旧注册项的安装，照旧把整个文件作为一次注入送达，英文副本也就照旧只剩预览。

钩子的回归测试核对：不带 `--part` 时注入内容与手册逐字节相等，`HOME` 指向空目录时也一样；每段不超过 9,500 个码元，段号连续、标签里的总段数一致，各段拼回去等于手册；手册需要的段数不超过设置里注册的段数。
