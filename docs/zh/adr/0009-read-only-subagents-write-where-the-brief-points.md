# ADR 0009：只读子智能体只在派发说明指定处写文件，retriever 把判断留给主线程

## 状态

已采纳，自 2026 年 10 月 1 日起生效。取代 [ADR 0008](0008-subagent-effort-per-kind-of-dispatch.md) 决策表里 `researcher` 与 `retriever` 的「限制」两格；ADR 0008 其余内容不变，包括各定义的推理强度与接什么活。

## 背景

ADR 0008 允许 `researcher` 与 `retriever` 新建文件，但没说建在哪里；`retriever` 只在遇到派发说明没要求的判断时才不下结论。这两处限制都留了缺口。

只读防护钩子 `subagent-readonly-guard.sh` 拒绝只读子智能体经编辑工具或 shell 命令改动已有文件，用 Write 或重定向新建文件则放行，因为要把发现落盘的只读派发得先建出那个文件。编排手册只在发现要落盘时才给只读派发一个产物路径（§2 第 2 条要素）。所以没给路径的派发，子智能体可以把笔记或临时脚本建在任何地方，包括用户的仓库里，留下未跟踪的散落文件。

`retriever` 跑在 `medium`，因为检索类在这一档测不出损失；判断类则是推理强度对比在 `medium` 下没能放行的那一类。派发说明要是问了一个答案本身就是判断的问题，比如某份配置能不能直接用于生产，主线程分错时它仍会落到 `retriever`。按原来的写法，这种问题算作派发说明要求了的判断，`retriever` 就用 `medium` 自己下了结论：被问一份配置能不能直接用于生产时，它直接给出了结论。

## 决策

| 定义 | 限制 |
|---|---|
| `researcher` | 只在派发说明给定的路径或系统临时目录下新建文件，不改任何已有文件；没给路径时，发现按派发说明要求的格式写进最终回复 |
| `retriever` | 文件限制与 `researcher` 相同；回报只有事实与证据，不下结论，派发说明问的问题答案是判断时，报出与之相关的事实，并写明这项判断留给主线程 |

主线程据以分派的描述从两边写明同样的边界。`retriever` 不接判断某样东西对不对、安不安全、好不好的问题，也不接答案可能落在仓库任何地方的搜索。`implementer` 会改文件、跑命令，不接设计还没定的活。

## 影响

没给产物路径的只读子智能体按要求不在用户仓库里留文件，做诊断时仍可以把复现脚本写到系统临时目录。钩子不强制这条路径限制，它靠定义里的要求，所以文件建到了别处属于定义没被遵守，防护钩子拦不住。

落到 `retriever` 的判断题以事实加点名的判断交回，由主线程自己下判断，或者再派 `researcher`。分错的派发要多派一次，换来的是不会有判断在主线程看不见的地方以 `medium` 做掉。在新写法下问同样的问题，两次运行里 `retriever` 都把它留作未决判断。
