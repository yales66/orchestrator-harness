# ADR 0019：保活唤醒前先探测网络，最后一次唤醒在还有工作时写交接

## 状态

已采纳，自 2026 年 10 月 8 日起生效。扩充 [ADR 0014](0014-idle-sessions-past-150k-keep-their-prompt-cache-warm-with-an-async-rewake.md) 与 [ADR 0015](0015-keepalive-keeps-timing-after-its-own-wake-up-and-skips-headless-sessions.md)，两者的条件、50 分钟睡眠与 8 小时上限不变。给 [ADR 0011](0011-wrap-up-finishes-in-session-at-any-watermark.md) 以及 [ADR 0010](0010-handoffs-are-generated-whole-by-the-handoff-skill.md) 所定 handoff 技能的第 0 步各加一个例外：保活的最后一次唤醒判定要交接时，立即生成交接，不先做收尾。

## 背景

`keepalive-gate.sh` 的唤醒开启一轮，这一轮的模型请求和别的请求一样要走网络。网络断了，请求就失败，这一轮结束时触发的是 StopFailure 事件而不是 Stop。Claude Code 忽略 StopFailure 钩子的退出码与输出，所以没有钩子能从那里唤醒模型，本该起下一次计时的 Stop 也不会触发。保活链因此每逢断网就断掉。2026 年 10 月 7 日，三个会话的唤醒都以 `ENOTFOUND` 结束，三个都没有再续上。

唤醒只在缓存还热时才划算。缓存在最后一次用到它的请求之后一小时过期，过期后的下一次请求要把整段上下文按缓存写入价重写一遍，所以来得太晚的唤醒比不保活还贵。Mac 睡眠期间 `time.sleep` 不走，合盖之后，按自己的计数睡满 50 分钟的钩子醒来时可能早已过了这一小时。

ADR 0014 在距用户本人最后一条消息满 8 小时后停止唤醒。在此之前上下文还能按缓存读取价读；唤醒停了、缓存过期之后，读它的任何一轮，包括写交接的那一轮，都要付重写的钱。

## 决策

唤醒模型之前，钩子先探测 API：向 `ANTHROPIC_BASE_URL` 发一个 HEAD 请求，未设置时发往 `https://api.anthropic.com`。收到任何 HTTP 响应都算连得上，4xx 与 5xx 也算，因为这说明请求到得了服务端。连不上时每 30 秒再探一次，直到钩子起跑后 57 分钟为止，即缓存一小时有效期减去 3 分钟余量。过了这个截止，钩子以退出码 0 退出，不唤醒。截止按墙钟比对，所以从 Mac 睡眠中醒来已过截止的钩子同样放弃。重试期间会话有了新的一轮，这次计时作废，与睡眠期间一样。首次探测前的睡眠按作者的选择仍是 50 分钟，于是截止前的最后 7 分钟留给重试。

下一次唤醒会越过 8 小时上限时，也就是钩子起跑时刻加两段睡眠距用户本人最后一条消息超过 8 小时时，这一次唤醒改为最后一次，提示也随之改变。提示告诉模型：会话还有要交给新会话接着做的事，就用 handoff 技能交接，走完该技能的全部步骤。只剩提交、推送、开拉取请求、合并这类收尾的会话，以及在等用户答复、答复后还有工作的会话，都算要交接，两种情况下模型这一轮都不做收尾，也不重新提问。任务已做完、剩下的只有用户本人能做，或已有的交接或计划文件已写全剩余工作且之后没有新进展时，模型只回一个句点。还有没有事要交接，只有模型从会话里看得出，所以提示把这一判断交给它。发过最后一次唤醒之后，无论模型怎样回答，钩子都不再计时，直到用户本人再发消息。

有三条规则若不改，都会把模型从这次交接引开，所以各自为它让出位置：

| 规则 | 对保活的规定 |
|---|---|
| 编排手册 §1 | 保活唤醒开启的回合只做其提示要的事，即回句点，或走完 handoff 技能的全部步骤，不附待答问题的提醒 |
| 编排手册 §3 | 「收尾在本会话做完、不交接」一条把最后一次保活唤醒判定要交接的情形除外；此时立即生成交接，不先做收尾 |
| handoff 技能第 0 步 | 最后一次保活唤醒判定要交接时跳过这一步自检，待答的问题原样写进派发说明的未完成项并标为待用户答，不重新提问 |

否决了两种做法：

| 做法 | 否决理由 |
|---|---|
| 由 StopFailure 钩子补救失败的唤醒 | Claude Code 忽略 StopFailure 钩子的退出码与输出，这样的钩子唤醒不了模型 |
| 不论多久都等网络恢复再唤醒 | 过了截止，缓存已过期或来不及续，再唤醒就要按缓存写入价重写整段上下文，比不保活还贵 |

## 后果

空闲会话遇上断网时，网络在截止前恢复，缓存就保得住；截止前没恢复，钩子不唤醒就放弃，会话在下一轮付重写的钱，与没有保活时一样。有一处补不上：探测连得上、紧接着的唤醒请求却失败时，这一轮以 StopFailure 结束，保活链就此断掉。

用户离开 8 小时而还有工作的会话，会在缓存还热时写好交接，handoff 技能按缓存读取价读上下文，用户回来时有一份新会话可以接着做的交接文件。没有东西要交的会话只回一个句点。

钩子测试覆盖：一直连不上直到截止、截止前网络恢复、重试期间用户回来、像合盖之后那样醒来已过截止、服务端回 404 算连得上、端口关着算连不上，以及最后一次唤醒的交接提示。
