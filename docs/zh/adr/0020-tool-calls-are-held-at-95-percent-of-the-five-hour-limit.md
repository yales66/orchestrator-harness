# ADR 0020：5 小时用量到 95% 时挂起工具调用，每 50 分钟保活一次

## 状态

已采纳，自 2026 年 10 月 8 日起生效。每轮 50 分钟以 [ADR 0014](0014-idle-sessions-past-150k-keep-their-prompt-cache-warm-with-an-async-rewake.md) 的一小时提示词缓存为前提，并放行 [ADR 0019](0019-keepalive-probes-the-network-before-waking-and-hands-off-at-its-last-wake-up.md) 的最后一次保活唤醒。

## 背景

Claude.ai 的 Pro 或 Max 订阅在每个 5 小时窗口里给定一份用量额度。用量撞上这个上限时，还在干活的会话与子智能体会在任务中途报错中断。

钩子的输入不带用量。Pro 或 Max 订阅下，会话收到第一次 API 响应之后，Claude Code 把 `rate_limits.five_hour.used_percentage`（0 到 100）与 `resets_at`（Unix 秒）传给状态栏命令，每个会话的值来自它自己最近一次响应。状态栏插件 claude-hud 装了的话，会保存一份用量缓存，最多每 5 分钟刷新一次，因为它查询的用量接口有限流。

PreToolUse 钩子超时会被取消，工具调用照常执行，默认超时为 600 秒。主线程的工具调用在钩子里等待期间，用户键入的消息由 Claude Code 排进队列，要等调用返回才送达，有一条这样的消息等了 36 分钟。

## 决策

`statusline-tee.sh` 包在状态栏命令外面：先把 `rate_limits` 写临时文件再改名，落盘到 `~/.claude/state/rate-limits.json`，再把标准输入原样交给作为参数传入的状态栏命令。同一窗口里，即两个重置时刻相差不到 10 分钟时，它从不用较低的值覆盖较高的值，因为很久没发请求的会话重绘状态栏时带的是旧的低值，而窗口内用量只增不减。它记下窗口第一次到 95% 的时刻为 `pause_since`，同一窗口里沿用。输入里没有 `five_hour` 字段时不动这个文件。

`limit-pause-gate.sh` 挂在所有工具的 PreToolUse 上，匹配符为 `*`，配 `"timeout": 3300`，主线程与子智能体都走，因为设置里的钩子在子智能体内同样运行。它读两个本地文件，即 `statusline-tee.sh` 写的那份与 claude-hud 的 `~/.claude/plugins/claude-hud/.usage-cache.json`，取其中重置时刻还没到的最高值，因为同一窗口里较低的读数必是旧值。读文件不发请求，不花额度。不到 95% 或读不到用量时，它不输出任何内容就放行，调用照常走权限流程。

达到或超过 95% 且未到重置时，钩子挂起这次调用。它睡到重置，每轮最多 50 分钟，每 3 秒看一次。重置在本轮之内到来就放行，不需要额外请求，因为缓存撑得过这段等待。否则睡满 50 分钟后拦下这次调用，理由要模型只经 Bash 发出暂停调用（`: 限额暂停`）。这次模型请求就是保活，只读缓存，输出几个词元，新的调用又被挂起。过了重置，钩子对暂停调用输出 `permissionDecision` 为 `allow` 放行，免得无人值守的交互会话卡在权限审批框上，模型随后重发被暂停的那个调用。用暂停调用代替原调用，是因为每轮原样重发会把它的整份输入再生成一遍，例如 Write 的全文。

三种情形不挂起：

| 情形 | 放行理由 |
|---|---|
| `~/.claude/state/limit-pause-off` 存在 | 这是手动的全局开关：`! touch ~/.claude/state/limit-pause-off` 关掉暂停，删掉该文件即恢复 |
| 主线程里，会话记录中最近一条输入是用户本人的（`origin.kind` 为 `human`），无论是开启一轮的提示还是回合中途键入的消息，且发在 `pause_since` 之后 | 用户在 95% 时不会拿剩下的额度做大事，这次调用由用户决定。不知道 `pause_since` 时不放行 |
| 最近一条输入是保活的最后一次唤醒 | 这一轮要写交接，挂过一小时就丢了交接要读的缓存。子智能体在主会话记录于这次唤醒之前没记下它的编号时也放行，这说明它是这一轮派出的，例如起草交接的 researcher；更早在后台派出的子智能体派出时编号已经记下，照常挂起，同步派出的子智能体活不过派出它的那一轮 |

其余一律挂起。越过 95% 之前就开始的一轮照常挂起，包括用户早先让它全自动跑的任务，因为用户开启它时并没有看到上限将至。用户的输入之后又来了后台通知、子智能体回报或最后一次以外的保活唤醒，之后的调用重新挂起，自动任务借不了用户开启的那一轮。其余子智能体一律挂起，包括用户在 95% 之后开启的一轮里派出的，因为豁免只覆盖用户本人对主线程的输入，而用量到了 95% 的用户不会再开大活。

挂起主线程的调用期间，钩子每 3 秒检查一次会话记录，看有没有新的 `queue-operation` 行，其操作为 `enqueue`、内容不是通知。发现一条，就立即拦下被挂起的调用，理由要模型先处理用户的消息、处理完就停，被暂停的工作留到重置之后。

出任何错钩子都放行，因为它拦在所有工具前面，不能把会话卡死。3300 秒的超时高于每轮 3000 秒，所以 Claude Code 不会取消钩子、放调用过去。

否决了两种做法：

| 做法 | 否决理由 |
|---|---|
| 每分钟刷新一次 claude-hud 的用量缓存 | 会撞上插件所查用量接口的限流 |
| 按哪个文件更新取读数 | 很久没发请求的会话重绘状态栏，会把旧的低值写成最新的一份，claude-hud 的缓存又滞后且取整，读数在 95% 上下来回跳，放过了本该挂起的调用。第一次真实触发暴露了这一点，所以钩子取最大值 |

## 后果

用量到 5 小时上限 95% 的会话或子智能体等到重置，不在工作中途报错，在此之前每 50 分钟一次请求保住它的提示词缓存。越过 95% 之后用户照样能做事，挂起期间用户键入的消息经队列检查几秒内就能送到。

状态栏包装与暂停都要求 Claude.ai 的 Pro 或 Max 订阅，因为 Claude Code 只在这两种订阅下把 `rate_limits` 传给状态栏。改 `statusLine` 设置对运行中的会话即时生效，不用重启，2026 年 10 月 8 日实测确认。

这一设计有三处已知局限。用量数据只在有会话收到模型响应时更新，所以几个同时忙碌的会话仍可能在两次读数之间越过 100%。多个状态栏同时写入可能短暂存下较低的值，下一次渲染会纠正。取两份文件最大值的修正还没有经过一次真实的 95% 窗口。

暂停经过单元测试、一次用 `claude -p` 与 haiku 配假用量文件的端到端运行，以及一次真实的夜间触发检验，那次跑的是按较新文件取值的旧版。端到端运行里，主线程被挂起，发出暂停调用，到重置时放行，再重发原来的调用；子智能体走了同样的循环，其中一次重发的是原调用而不是暂停调用，钩子照样把它挂起。2026 年 10 月 8 日的夜间触发里，钩子每轮挂起 50 分钟，连续四轮，可见 Claude Code 遵守 3300 秒的超时，其文档也没有写超时上限。
