# ADR 0026：交接由主线程自己写，接力会话由会话自己拉起

## 状态

已采纳，自 2026 年 10 月 15 日起生效；10 月 23 日与 24 日补上的接力分支与措辞也包括在内。本决策修订 [ADR 0010](0010-handoffs-are-generated-whole-by-the-handoff-skill.md) 所定 handoff 技能的步骤：去掉生成与审稿两步、起草用的 `researcher` 以及路由文件，步骤重新编为 0 到 4，末尾加一步接力。ADR 0010 的以下规定不变：`HANDOFF.md` 只经这个技能整份生成；抽取从会话记录读出用户每一种形式的输入；`finalize.sh` 把文件落位并归档旧版；`handoff-guard.sh` 禁止手改。[ADR 0019](0019-keepalive-probes-the-network-before-waking-and-hands-off-at-its-last-wake-up.md) 给第 0 步加的例外，现在是第 0 步的 B 分支。编排手册原先「用一句起手指令请用户换会话」的做法由第 4 步取代。

## 背景

按 ADR 0010，主线程先抽取用户输入、写简报，再由一个不带主线程语境的 `researcher` 据此起草 `HANDOFF.new.md` 与路由文件，最后主线程审稿。作者 2026 年 10 月 7 日至 14 日的会话里共有 69 次交接，每次中位花费 2.57 美元，其中起草子智能体 1.30 美元，主线程审稿与落位 0.89 美元，起草和审稿占了大头。

为检验审稿值多少，作者在两个取自私有项目的交接用例上做了回放。两份简报里共有 5 处已知错误；接手的会话动手时自己抓到了其中 4 处，起草的 `researcher` 历次只抓到 2 到 3 处。接手方做某一项时会读那一项依赖的前提，所以交接里的错误大多会在要紧的地方被发现。

交接时主线程上下文中位约 360,000 词元，按 API 等价价格每次调用约 0.09 美元，一次交接中位 11 次调用；这些数字来自作者的会话记录，记于 2026 年 10 月 13 日。这时主线程每多一次调用，就要把整段上下文再读一遍。

交接写完后，会话请用户用一句起手指令开新会话，工作一直等到用户回来。

## 决策

handoff 技能按以下步骤运行：

| 步骤 | 做什么 |
|---|---|
| 0. 自检 | 取第一条成立的分支。A：没有要会话做的事，也没有待用户答复的问题；停掉唤醒、收好任务清单，不写交接，旧 `HANDOFF.md` 存在时只写首行与 ⑤。B：用户要求交接，水位钩子再次拦下，或保活最后一次唤醒判定要交接；往下走。C：只剩收尾；不交接，回去做完。D：某个 B 型问题后面跟着一大块工作；用文字提问，做完不依赖答复的部分，后台 `sleep 3000` 等待。E：其余情形往下走 |
| 1. 目录 | 本任务的工作目录，已有 `HANDOFF.md` 时取它所在目录 |
| 2. 生成 | 在一条消息里并行发出：(a) 主线程自己一次写成 `HANDOFF.new.md`，不派子智能体起草，也不另行审稿；(b) 用绝对路径把 `.handoff-archive/` 加进仓库本地的 git 排除，再抽取到 `<dir>/.handoff-archive/material/`；(d) 停掉定时唤醒与定时任务。上下文里有压缩摘要的会话先跑 (b)，读过用户原话再写 (a)。之后 (c) 把跨任务有效的内容按 `memory-audit` 的准入判断落盘 |
| 3. 落位 | 第 2 步之后有新情况就先改稿，定下第 4 步走哪一支，更新任务清单，再跑 `finalize.sh` |
| 4. 接力 | 先把任务清单里未完成的项改成 blocked 并写上交接路径，再取第一条成立的分支。A：分片的 `PARENT.md` 或轨道的收尾约定另有接力规定；照做。B：每个未完成项都在等一个 B 型问题，或者没有要会话做的事，或者用户会自己开新会话；告诉用户交接路径与起手指令后停下。C：起手项要用一个在跑任务的产物，该任务完成时会通知本会话；等它，后台 `sleep 3000` 作上限，更新该项后按 D 拉起。D：用 `feature-sharding/scripts/launch_tracks.py` 在新的 Ghostty 窗口里拉起接力会话，命名为 `<仓库目录名>-R<n>` |

证据按接手方的需要写，不再为审稿者写。数值、路径与阈值写本会话实测或读到的值，没核过的标「未核」，不为写交接另去取证。② 里的约束即使已经写进项目记忆也照引用户原话；只能逐字保留的约束，例如设计口味或被否掉的措辞，把用户原话与被否原文全文照抄。

## 后果

一次交接只花主线程自己的调用，不再派子智能体。这里没有记录改动之后的实测花费；上面的数字是被去掉的那几步的花费。

稿子落位之前没有第二个读者核对，主线程写错的内容会原样到达接手方。回放显示接手方在做受影响的那一项时能抓到大多数已知错误；回放只有两个用例，而接手方从不去做的那一项里的错误不会被抓到。

抽取结果放在仓库内的 `.handoff-archive/material/`，本地排除让用户原话全文不出现在 `git status` 里，也不会被提交。本地排除只对当前克隆有效，不进提交。

会话不等用户就把工作接下去：除非要先等用户答复，或者没有要会话做的事，否则会在新窗口里拉起接力会话。第 4 步 D 依赖 macOS 与 Ghostty，因为 `launch_tracks.py` 经 AppleScript 操纵 Ghostty；拉起失败时会话按 B 分支处理，把报错原文告诉用户。在别的平台上，每次接力都走 B 分支。

`verify_refs.py` 原本服务于起草的 `researcher`，上游随它一并删除，本仓库不发布。
