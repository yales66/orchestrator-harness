# ADR 0010：交接文件由 handoff 技能整份生成，钩子禁止手改

## 状态

已采纳，自 2026 年 10 月 4 日起生效。取代 ADR 0004 放在编排手册 §3 的交接格式，交接格式改由 handoff 技能定义；ADR 0004 读取水位的做法不变。取代 ADR 0006「持续或条件授权」一行里要跨会话延续的授权写进项目记忆、交接时也写进交接文件的规定；ADR 0006 其余内容不变。

## 背景

主线程手写的交接文件会与它描述的会话脱节。后来的会话在同一份文件上原地打补丁时，决策段只增不减：约束的工作做完了，条目还留着，没有谁去删。「用户原话写进交接」这条规则只在落笔那一刻起作用，补丁不会回头扫一遍整段对话，于是用户在会话早些时候做的决定可能漏掉，而且没人察觉。

用户的输入可以从会话记录里机械地读出来，前提是认得它的每一种写法。Claude Code 记录选择题的回答时，开头有两种措辞。只认其中一种的抽取，会漏掉所有以「The user answered:」开头的回答：在本决策之前的七天里，它在 31 个会话中丢了 40 条回答，每一条都可能带着一次授权或否决。

交接格式与取证规则原先写在编排手册 §3，而编排手册只送达主线程（ADR 0001）。派去写交接的子智能体读不到这些规则，除非主线程把它们抄进派发说明。

## 决策

`HANDOFF.md` 只经 handoff 技能生成，每次都整份生成；已有的交接文件与本任务的进度源是新交接的材料，不是打补丁的对象。进度写进本任务自己的进度源，没有就写进只追加的 `PROGRESS.md`，`HANDOFF.md` 不算进度源。技能按下列步骤运行：

| 步骤 | 做什么 |
|---|---|
| 抽取 | `scripts/extract.py` 读会话记录，按时间顺序编号写出用户给过的每一条输入，包括键入的消息、斜杠命令、两种措辞的选择题回答与被拒绝的工具调用，并写出本任务涉及的每个仓库的 git 状态。`--transcript` 必填，因为同一项目里并行的另一个会话可能拥有最新的会话记录文件 |
| 派发说明 | 主线程只写抽取结果与仓库都给不出的内容：用户原话里的目标、各未完成项及其核对办法、实跑过的关键命令与结果、仍约束剩余项的选择、在跑的任务和查出的坑 |
| 生成 | 一个不带主线程语境的 `researcher` 按技能里的结构与取证规则，从派发说明、抽取结果与旧交接写出 `HANDOFF.new.md` 与一份分流文件；这些规则写在技能里，它读得到。只读守卫让它能新建这两个文件，但建好后改不了，所以它先核后写，写完才发现的错写进回传，不去改文件 |
| 审阅 | 主线程按顺序取第一条成立的分支。抽取之后有影响未完成项的新输入或仓库变化：重新抽取并更新派发说明。派发说明要改动未完成项的构成，或稿子的未完成项与派发说明不符：删掉稿子，用 SendMessage 把不符处发给同一个 `researcher` 重写。其余错漏：主线程直接改稿。无错：进下一步。只有消息送达不了时才重新派发 |
| 落位 | `scripts/finalize.sh` 把 `HANDOFF.new.md` 放到位，旧版归档到 `.handoff-archive/` |
| 分流 | 分流文件里跨任务长期有效的条目，经 `memory-audit` 的准入判断写进项目记忆；只约束本任务剩余工作的授权由交接文件带过去 |

让原 `researcher` 修改它的草稿，那一次派发花 $0.16 到 $0.31；为同一份交接重新派发一个 `researcher`，那一次派发花 $0.61 到 $1.26，因为原 `researcher` 已经读过材料。这两组数只算那一次派发，不是整次交接的花费。它照样不带主线程的语境，所以把生成交给不带语境的子智能体的理由不受影响。

`hooks/handoff-guard.sh` 在 PreToolUse 上匹配 `Edit|Write|MultiEdit|NotebookEdit|Bash`，主线程与子智能体一律适用。目标文件名恰为 `HANDOFF.md` 的编辑或写入被拒绝；原地写它的 shell 命令也被拒绝，包括重定向、`tee`、就地的 `sed`、`perl` 或 `awk`、`ed` 或 `ex`、`truncate`，以它为源或目标的 `cp`、`mv`、`rm` 或 `ln`，指向它的 `git checkout`、`restore`、`rm` 或 `mv`，以及提到它的内联解释器代码。读它、写 `HANDOFF.new.md` 与运行 `finalize.sh` 都放行。上下文水位闸门的拦截理由改为指向 handoff 技能，并附上抽取一步要用的会话记录路径。

## 后果

每份交接都从用户说过的全部内容重建，所以会话早期做的决定能带到下一个会话，只关乎已完成工作的条目随那项工作一起消失。每份交接要派一次 `researcher`，在作者的会话里整次交接的花费中位数是 $1.88（27 次交接，含主线程的抽取、写派发说明与审阅），这也是编排手册 §3 不为收尾写交接的原因（ADR 0011）。

守卫防的是模型顺手的补丁动作，防不住刻意的绕过，例如用一个脚本文件去写交接，因为执行脚本文件的调用看不到代码。编排手册的「接手」一条引用交接的 ⑤ 段，⑤ 由技能定义，所以编排手册与技能必须一起发布。守卫按 ADR 0005 带回归测试，抽取与落位脚本带 pytest 测试，其中包括选择题回答的两种开头。
