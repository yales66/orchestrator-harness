# ADR 0014：上下文过 150k 的空闲会话在 50 分钟后由异步唤醒保住缓存

## 状态

已采纳，自 2026 年 10 月 4 日起生效。取代 [ADR 0013](0013-sessions-past-150k-keep-their-prompt-cache-warm.md)；ADR 0013 的背景、150,000 词元的阈值与 8 小时上限不变，变的是触发保活的机制。与 [ADR 0011](0011-wrap-up-finishes-in-session-at-any-watermark.md) 的互补关系同 ADR 0013。

## 背景

ADR 0013 让 Stop 钩子拦停，要模型用 CronCreate 设一个每 30 分钟一次的重复任务。这样做出了两个问题。定时任务按钟点触发，用户离开时触发，用户在场时也照样触发，一小时两次，用户正在用的会话里每一次触发都是省不下任何东西的请求。自动模式的分类器还把这次 CronCreate 判为未经授权的持久化（Unauthorized Persistence）并拒绝，于是在自动模式下保活从来设不上，拦停只是打断了那一轮。重复任务 7 天过期的上限无关紧要，因为 8 小时上限远早于它结束保活。

Claude Code 允许命令钩子设 `"asyncRewake": true`：钩子在后台运行，以退出码 2 退出时，它的标准错误作为提醒唤醒空闲的会话。2026 年 10 月 4 日，一个配了这项设置、`"timeout": 900` 的探针 Stop 钩子分别睡了 40 秒与 660 秒，两次都唤醒了会话，可见钩子的超时可以设到 600 秒以上。唤醒以一条用户角色、以 `<task-notification>` 开头的消息进入会话记录。

每一轮结束后，Claude Code 自己会往会话记录追加几行：几毫秒内追加 `stop_hook_summary` 与 `turn_duration`，空闲几分钟后追加 `away_summary`。这些行不是新的一轮。

## 决策

`keepalive-gate.sh` 挂在 Stop 上，配 `"asyncRewake": true` 与 `"timeout": 3300`。主线程每一轮结束后，它先查 ADR 0013 查过的那些条件：在子智能体内部或 `stop_hook_active` 为真时、主线程上下文不到 150,000 词元时、主线程最近一次缓存写入用的是 5 分钟有效期时，以及距用户本人最后一条消息超过 8 小时或根本没有这样的消息时，它什么也不做。其余情况下它记下会话记录当前的末尾，睡 50 分钟。

醒来后，会话记录若已不在、变短了，或记下的末尾之后多了 `user` 或 `assistant` 行，它就以退出码 0 退出，因为会话有过新的一轮，那一轮结束时已经起了新的计时。否则它向标准错误写 `[保活] 只回复一个句点，不做别的。` 并以退出码 2 退出，唤醒模型只回一个句点。其他类型的行，例如 Claude Code 在一轮结束后自己追加的那些，不算活动。

保活那一轮结束时又触发 Stop，起下一次计时，于是空闲的会话每 50 分钟被唤醒一次，直到距用户本人最后一条消息满 8 小时。唤醒是一条后台通知，所以它与子智能体回报、别的会话发来的消息、`isMeta` 消息一样，不算用户本人的消息。

取 50 分钟，唤醒落在缓存一小时的有效期内，还给提醒排队与请求执行留出十分钟余量。3300 秒的超时比 3000 秒的睡眠多出五分钟，够睡前睡后各读一遍会话记录。

## 后果

保活只在用户离开时触发：用户一直在用的会话睡不满 50 分钟，从不被唤醒。上下文过 150,000 词元的空闲会话每次唤醒约付 $0.06，一小时略多于一次，而不是在用户、通知或唤醒下次到来时付几美元的重写。空闲超过 8 小时的会话不再被唤醒，照旧付重写的花费。

不建任何任务，所以除了钩子自己的后台进程，没有东西留存下来，自动模式没有可拒的操作，`/clear` 之后或到 8 小时上限时也没有要删的东西。

50 分钟的睡眠以一小时的缓存为前提。缓存降为 5 分钟后，钩子不起计时。
