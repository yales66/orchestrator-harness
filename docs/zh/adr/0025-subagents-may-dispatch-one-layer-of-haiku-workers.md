# ADR 0025：子智能体可以再派一层 haiku 工人

## 状态

已采纳，自 2026 年 10 月 14 日起生效。本决策修订 [ADR 0003](0003-subagents-cannot-spawn-subagents.md)：子智能体调用 `Agent` 或 `Task` 时，只要把模型设为 haiku 就放行，这些工人不能再往下派。子智能体内的其余派发，包括 `Workflow`，仍一律拒绝；ADR 0003 按 `agent_id` 判定、输入异常时放行这两点不变。对一类问题，本决策还修订 [ADR 0023](0023-implementer-runs-on-haiku-when-tests-decide-including-its-own.md) 重申的「只能靠看来判定的工作仍派 opus」：端到端测试里针对单个元素裁图的是否题派给 haiku。

## 背景

按 ADR 0003，子智能体每一步都自己做。端到端测试一类的工作里，很多步骤是机械短活，例如汇总一次测试运行、对照来源核对文案、回答某个裁出来的元素有没有被截断；长时间运行的子智能体每走一步都要重读整段上下文。2026 年 10 月 14 日，用户选定让子智能体把这类活交给 haiku，以减少步数。

同一天作者在这些活上测了 haiku：测试结果汇总 8 次全对，文案核对 8 次全对，单元素裁图是否题 13 次对 12 次，唯一失手是答了「判断不了」。这次实测里工人上下文最长约 42,000 词元。

Claude Code 的 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 限制嵌套层数；按上游提交引述的官方文档，设为 2 时子智能体可以再派一层，那一层不能再派。2026 年 10 月的官方价目规定，Haiku 单次提示超过 100,000 词元时整次请求按五倍计价。

## 决策

两份副本的 `settings.example.json` 都把 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 设为 `2`。`hooks/block-nested-subagent.sh` 仍在 `Agent`、`Task` 与 `Workflow` 的 `PreToolUse` 上运行，仍按 `agent_id` 判定。在子智能体内，`tool_input.model` 为 `haiku` 或以 `claude-haiku` 开头的 `Agent` 或 `Task` 调用放行，其余一律拒绝；拒绝理由改为：只能派模型显式为 haiku 的工人，做短活，上下文控制在 50,000 词元以内，其余拆分写进返回值交给编排者。

编排手册 §2 规定派发一方怎么做：

| 事项 | 规则 |
|---|---|
| 谁可以派工人 | 除 `retriever` 以外的子智能体；`retriever` 的定义已去掉 `Agent` 工具 |
| 派什么活 | 只派机械短活：跑测结果汇总、文案核对、单元素裁图上的是否题、场景里机械错误的修改建议（改完必须重跑该场景） |
| 工人的输入 | 只给路径与问题，上下文控制在 50,000 词元以内 |
| 主线程的派发说明 | 写明这个子智能体可以派哪些活、上下文上限多少 |
| 端到端测试的裁图题 | 单个元素裁图上的是否题，例如文字有没有被截断、重叠或看不清，派 haiku；haiku 报出的问题经 opus 复看后才算数 |

50,000 词元的上限取自实测最长的工人上下文约 42,000 再取整；超过 100,000 词元按五倍计价，是要远离那条线的理由。

手册同一节还把发给在跑子智能体的消息分成两支，因为每条消息都会让它多走几步，每一步都重读整段长上下文。A 支即时发，只发给受影响的子智能体，包括它不知道就会做错、白做或记成错误结论的内容，以及判断不清有没有影响的内容。B 支是其余一切，例如不改变产出或结论的措辞更正，有下一次续用或派发就顺带，没有就不发。进度询问一律不发。

## 后果

派发现在可以有两层，但只有第二层的模型是固定的，而且那一层不能再往下派：嵌套层数设置让工人那一层拿不到 `Agent` 工具。编排者没有规划过的分发，只限于派发说明点名的活、由 haiku 工人来做；子智能体内的 `Workflow` 仍被拒绝。

测过的活很窄，样本也小，分别是 8、8、13 次。haiku 在裁图题上唯一的失手是弃答而不是答错，haiku 报出的问题又都经 opus 复看，所以误报的代价是一次复看；haiku 漏报的问题没有人复看。要看整个界面而不是单个裁出元素来判定的工作仍派 opus。

钩子对子智能体内任何显式 haiku 调用都放行，工人发起的也一样，所以第三层只靠嵌套层数设置拦住；`settings.json` 里没有这项设置的安装依赖 Claude Code 的缺省层数，本仓库没有测过这个缺省值。

钩子的回归测试用 7 个用例钉住新分支，这是 [ADR 0005](0005-deciding-hooks-ship-with-regression-tests.md) 对作决定的钩子的要求：在子智能体内，模型为 `haiku` 的 `Agent` 与 `Task` 放行，写全名、大小写不同也放行；`opus`、不写模型、名字只是含 "haiku" 的模型，以及即便带 `haiku` 的 `Workflow`，都拒绝。把条件改成拒绝所有 haiku、放行所有模型、或放行名字含 "haiku" 的任意模型，都至少有一个用例变红。
