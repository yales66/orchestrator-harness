# ADR 0029：任务已完成或已交接的会话停止保活，有在跑轨道的分片父会话保持保活

## 状态

已采纳，自 2026 年 10 月 24 日起生效；各部分在 2026 年 10 月 8 日至 24 日间陆续进入作者在用的配置。本决策扩充 [ADR 0014](0014-idle-sessions-past-150k-keep-their-prompt-cache-warm-with-an-async-rewake.md)、[ADR 0015](0015-keepalive-keeps-timing-after-its-own-wake-up-and-skips-headless-sessions.md) 与 [ADR 0019](0019-keepalive-probes-the-network-before-waking-and-hands-off-at-its-last-wake-up.md)：50 分钟睡眠、5 分钟缓存有效期的检查、跳过无头会话、网络探测与 57 分钟截止都不变。改动有四处。钩子也挂在 `SessionEnd` 上。它只读会话记录里 `user` 与 `assistant` 两类行。唤醒可以回「完」，回了就停止保活。有在跑轨道的分片父会话低于 150,000 词元也保活，8 小时上限从更晚的活动起算。ADR 0019 的最后一次唤醒里，只剩收尾的会话改为记一份收尾清单，不写交接。

## 背景

`asyncRewake` 的唤醒打进的是 Claude Code 进程当下持有的会话，而计时盯的是起跑时那个会话的会话记录。`/clear` 或 `/resume` 之后旧会话记录不再变化，旧计时到点就把唤醒打进新会话，让它白白初始化一次。

从 Claude Code 2.1.300 起，会话记录里还有 `api-request-blob` 类型的行，带用户角色的消息，却没有时间戳。钩子把它们当成用户本人的消息，用户最后一条消息的时间被冲成空值，上下文过 150,000 词元的会话从此完全不再计时；作者的会话记录里，最后一次生效的唤醒在 2026 年 10 月 20 日 14:28（UTC）。

按 ADR 0014，已完成的会话照样每 50 分钟被唤醒一次，直到 8 小时上限，因为只有模型看得出任务做没做完。已交接的会话处境相同：剩余工作和用户的答复都去接力会话。2026 年 10 月 21 日至 24 日，有 3 个会话在交接之后共收到 7 次唤醒，每次都回了句点：当时的提示只在没有待用户答复的问题时才允许回「完」，而交接过的会话末尾几乎总挂着交接带过去的问题。

`feature-sharding` 以后台会话运行轨道之后（ADR 0028），规划会话作为父会话空闲等待，轨道一停下就一定唤醒它。它的上下文小时落在 ADR 0013 的 150,000 词元阈值以下，不计时；它的 8 小时上限从用户最后一条消息起算，轨道还在干活也照算。上游提交对唤醒时的重写这样计价：Opus 5.5 的 1 小时缓存写入每百万词元 8 美元，缓存读取 0.20 美元，前者是后者的 40 倍。

ADR 0019 的最后一次唤醒只要还有工作就写交接，只剩收尾也一样。2026 年 10 月 6 日至 13 日落位的 42 次交接里，有 13 次由最后一次保活唤醒触发，按 API 等价价格每次约 2.9 美元。只剩提交、推送、开拉取请求或合并时，新会话从 git 状态就看得出还剩什么。

## 决策

| 改动 | `keepalive-gate.sh` 怎么做 |
|---|---|
| 已结束的会话 | 也挂在 `SessionEnd` 上，在 `~/.claude/state/keepalive-ended` 下留一个以会话 id 命名的空标记，并删掉一天前的标记。计时期间与唤醒之前，见到本会话的标记就退出 0 |
| 会话记录的行 | 消息与活动只从 `user` 或 `assistant` 类型的行读取 |
| 「完」 | 句点唤醒的提示有两个分支让模型只回一个「完」字。A：任务已做完，没有待用户答复的问题，也没有在跑的后台任务或子智能体。B：本会话已用 handoff 技能写出交接文件，把剩余工作交给别的会话，剩余工作、待答问题与在跑任务都写进了交接文件，之后除交接里登记过的任务发来完成通知外没有新进展。回了「完」之后，直到用户本人发下一条消息（含回答选择题）都不再计时。唤醒前再读一遍会话记录，因为「完」那一行常在钩子起跑之后才写入，比较前去掉引号与句末标点 |
| 分片父会话 | `~/.claude/state/sharding/parents/<会话 id>.json` 存在，且其状态目录里有尚未结束、也没有声明完成的轨道，或有已登记但还没有状态文件的轨道时：150,000 词元阈值不适用，「完」不停止计时，8 小时上限与最后一次唤醒从用户本人最后一条消息与最近一次轨道状态两者中较晚的那个起算。任何读取失败都按没有在跑轨道处理 |
| 最后一次唤醒 | 提示按第一条成立的分支走。A：还有要新会话接着做的实质工作，或有待用户答复的问题；走完 handoff 技能的全部步骤。B：只剩收尾（提交、推送、开拉取请求、合并、在跑任务回报后收尾），可以夹带用户本人要做的事；在进度源末尾追加一节，逐条写出每个动作及其核对命令、在跑任务的产物路径，然后回一个句点。C：任务已做完，只剩用户本人能做的事，或已有的交接或计划文件已写全剩余工作；只回一个句点。这一轮不做收尾，也不重新提问 |

编排手册 §3 写明最后一次保活唤醒不做收尾、按提示记收尾清单；§1 列出保活回合可以给的三种回复。

## 后果

被 `/clear` 或 `/resume` 换掉的会话不再被旧会话的计时唤醒。对 `api-request-blob` 行的修正恢复了计时；这也说明钩子依赖会话记录的格式，而这个格式可能随 Claude Code 版本变化。

已完成或已交接的会话再多一次唤醒就停下，不再一直续到 8 小时上限；这一次唤醒是把判断交给模型的代价。被模型误判为已完成的会话会失去热缓存，直到用户发下一条消息。

分片父会话在轨道运行期间保持热缓存，代价是即使上下文很小也每 50 分钟唤醒一次。40 倍的比较是上游提交按价目做的算术，不是在这些会话上实测的。

只剩收尾的会话在进度源里得到一份清单，而不是一整份交接；收尾本身仍等用户回来做，所以无人在场时不会推送或合并。

两份副本的钩子里提示都是中文字符串，钩子按「完」字比对回复，所以英文副本的模型也用这个字回复。
