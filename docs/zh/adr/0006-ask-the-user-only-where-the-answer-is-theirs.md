# ADR 0006：只在答案属于用户时才问用户

## 状态

已采纳，自 2026 年 9 月 29 日起生效。其中翻会话记录派哪个子智能体，由 [ADR 0008](0008-subagent-effort-per-kind-of-dispatch.md) 取代。「持续或条件授权」一行里要跨会话延续的授权写进项目记忆并写进交接文件的规定，由 [ADR 0010](0010-handoffs-are-generated-whole-by-the-handoff-skill.md) 取代：跨任务长期有效的写进项目记忆，只约束本任务剩余工作的由交接文件带过去。「收尾时的下一步」一行里把合并归为对外动作的规定，由 [ADR 0012](0012-merging-own-pr-is-undoable-outside-production.md) 取代。「收不回的动作」一行里用 AskUserQuestion 确认的规定，由 [ADR 0017](0017-decisions-are-asked-in-text-and-askuserquestion-is-denied.md) 取代：改为用文字提问确认，并结束本轮。

## 背景

智能体每停下来问用户一次，工作就要等到用户再发一条消息才能继续。这类提问里有很多针对的是用户当前目标之内、做错了也能复原的下一步，例如顺手更新一个相关文件、推送个人分支，用户几乎总是同意。回复以提议这类下一步的问句收尾（「要我顺手把 README 也更新吗？」）效果相同：本可直接做完的一步变成一轮等待，用户还得回来只为说一句「做吧」。

也有一些问题确实属于用户。交易、转移资金、删除数据这类收不回的动作，做了就无法事后补救，必须由用户确认。各分支做出的东西实质不同、取舍又取决于只有用户知道的偏好或约束的分叉，从仓库里得不出答案。还有一些问题看似要用户拍板，其实是事实，例如某件事做没做过、测没测过，仓库与 git 历史往往就能回答，用不着问用户。

## 决策

编排手册按情形规定智能体何时提问：

| 情形 | 智能体怎么做 |
|---|---|
| 收不回的动作 | 可逆的准备照做，到收不回的那一步之前用 AskUserQuestion 确认 |
| 方向有分叉 | 各分支做出的东西实质不同，且取舍取决于只有用户知道的偏好或约束，才问用户；否则按推荐分支做，开头一句话说明选了哪支和理由 |
| 收尾时的下一步 | 在用户当前目标之内、做错了可逆、不对外也不调用付费服务的，直接做完再汇报。可逆包括改受 git 跟踪或已有备份的文件、推个人分支、开不指派审阅人的草稿 PR；对外包括合并、部署、发消息或邮件、提交申请或表单、公开发布、写共享数据库；付费服务包括按量计费的模型接口、付费数据源与云资源，派子智能体不算 |
| 持续或条件授权 | 在本会话余下时间内有效，只覆盖授权时所指的对象与改动，新增范围不继承，用户改口即撤销；要跨会话延续的授权写进项目记忆，交接时写进交接文件 |
| 关于事实的提问 | 先查仓库与 git 历史，需要翻会话记录时派 researcher 去查，查不到再问，并说明查过哪里 |

确实需要用户拍板时，每个待定项写清背景、各选项对用户的影响和智能体的推荐，不引用会话内部编号或自造术语。

`hooks/reply-gate.sh` 在 `Stop` 事件上检查回复怎样收尾。最后一个非空段落的末句是「要我…吗」「需要我…吗」「Shall I …?」这类提议问句时，它拦停一次，拦截理由重申收尾时的判据以及请用户拍板的写法。检查前先剥掉围栏代码块、行内代码与 URL；问句出现在中间段落，或末段问句之后还跟着陈述，说明动作已经决定，不算。已经因 `Stop` 钩子续跑的停止一律放行，所以它不会连续拦截两次。

## 后果

可逆、在目标之内、不对外也不付费的下一步会直接做完再汇报，而不是停下来提议，用户看到的是已经做完的结果，需要时可以复原。收不回的、对外的和付费的步骤仍然等用户决定，取决于用户自身偏好的分叉也一样。代价是智能体有时会做出用户本不会选的一步，收尾判据的几项条件把这种情况限制在可以复原的步骤上。

回复出口检查靠一组固定的中英文措辞识别提议，换一种说法的提议会漏过。用户确实需要回答的问题如果恰好以这些措辞收尾，会多花一轮：钩子拦一次，智能体保留这个问题并补上背景、后果与推荐，下一次停止即放行。这个钩子按 ADR 0005 带有回归测试。
