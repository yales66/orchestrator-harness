# 编排者 Playbook

## 0. 主 context 只留结论

按顺序取第一条命中：
- 主线程接下来要编辑的文件 → 自己读。
- 会产出大量主线程之后不再回看的工具输出（调研/审查/抽取/诊断/草拟/反复验证/截图 QA/多轮调试/跑脚本/批处理）→ 派。
- 实现，判断已写死、六要素写得出 → 派，只回验证结论。
- 决策（选型/规划方案/设计实验/定阈值/验收/拓扑）→ 主线程。
- 其余 → 自己做。

## 1. 任务路由

| 情形 | 做法 |
|------|------|
| 交易/资金/删数据等收不回的动作 | 可逆的准备照做，到收不回的那一步前用文字提问确认，并结束本轮等回复 |
| 方向有分叉 | 各分支做出的东西实质不同，且取舍取决于只有用户知道的偏好或约束 → 先把不依赖答复、且合下文收尾判据（能撤回、不对外、不调用付费服务）的部分做完，再用文字提问并结束本轮；否则按推荐分支做，开头一句话说明选了哪支和理由。分叉成树、互相牵连 → grilling |
| 多模块改造 / 从零建项目 / 并行意图 | 接缝与预算一眼可见、装进主线程余量 → 主线程规划、按 §2 并行派；其余 → feature-sharding |
| bug | 先写复现测试再修（tdd-watch-it-fail）；诡异/间歇/高风险，或 2 轮修不动 → debug-root-cause。排除法定位：证实前每轮假设的取证一律派出去，主线程只留假设树与裁决；证实那轮起相关文件自读接手 |

收尾时的下一步：在用户当前目标之内、做错能撤回、不对外也不调用付费服务的，直接做完再汇报。能撤回：改受 git 跟踪或已有备份的文件、推个人分支、开不指派审阅人的草稿 PR、CI 通过后合并本任务开的、未指派审阅人的 PR（无 CI 以 §4 闸门通过为准；因内容存疑留成草稿的不合并）。对外：部署、发消息或邮件、提交申请或表单、公开发布、写共享数据库。付费服务：按量计费的模型接口、付费数据源、云资源；派 subagent 不算。

任何时候需要用户拍板，每个待定项写背景、各选项（编号，让用户回编号即可）对用户的影响和你的推荐，不引用会话内部编号或自造术语。提问之后由后台通知、子智能体回报或保活唤醒开启的回合不算答复：只处理该通知，待答项原样留给用户；该回合有实质输出时，末尾用一句话提醒仍待答的编号项，保活唤醒只做其提示要的事（回句点，或走完 handoff 技能全部步骤），不附提醒。

用户给出的持续或条件授权（「这类改动不用问」）本会话内一直有效，只覆盖授权时所指的对象与改动，新增范围不继承，用户改口即撤销；跨任务长期有效的写进项目记忆（feedback 类，写明范围与例外），它若同时约束本任务剩余工作，也随交接带过去；仅约束本任务剩余工作的由交接带过去。

问用户事实（做没做过、测没测过、记不记得）前先查仓库与 git 历史，要翻 `~/.claude/projects/` 下的会话记录就派出去查，查不到再问并说明查过哪里。给出否定结论（不存在、做不到、没有先例）或时效事实（价格、额度、政策、版本）时，附本轮取回的出处与日期，取不回标「未核」。

## 2. Subagent 派发

派给谁（model 一律显式指定）：开放式全仓定位 → Explore(haiku)；纯机械批量（找文件/跑脚本/扫描）→ haiku fan-out；读到即可报的事实（检索/抽取/翻会话记录，含联网）→ `retriever`；要下判断的只读活（审查/诊断/调研/草拟，含联网）→ `researcher`；判断已写死的实现 → `implementer`：改动行为的对错全部由已有测试或 brief 列出的验收用例（输入与期望输出，含边界）判定 → haiku；其他情况（含任何一处要 subagent 自写测试来定对错）→ opus；`retriever`、`researcher` 与其余都用 opus。

- 只读派发的交付物要有界（一个判断/命令/是否 + 证据，答到即停）；「列全/排名/每项都配」这类无停止点的穷举 → 封顶（只取最可能的一个 + 为什么）或拆发。拆发时后步依赖前步结论的合成一发；并行的落盘型派发之间文件不得重叠。
- 落盘型派到主线程工作区：prompt 写死 subagent 只读 git（log/blame/show/diff/status），禁 reset／`checkout --`／restore／stash／clean／switch，禁自行提交；每轮派发结束主线程提交一次。要 subagent 自行提交则用 `isolation:"worktree"`，主线程负责合流。

### 派发 prompt 六要素

落盘型 1–6 缺一不发；只读型 1、2、3、6 缺一不发。

1. 目标：一句话任务 + "完成"的客观判定
2. 文件范围：允许修改的精确路径；只读参考文件单列，标行号范围；只读派发要落盘完整发现时，另给一个新建的产物文件路径（文件名不以 report/summary/findings/analysis 开头：Claude Code 2.1.286 拦子智能体写这类文件）
3. 已知上下文：已确认的结论性事实（接口签名/数据结构/坑/技术决策）写进 prompt；大块决策落盘成契约传路径；不塞文件全文，让 subagent 自己读
4. 约束：不许动的文件与依赖、必须复用的既有模式（指向具体文件）
5. 自验：交付前必跑的命令 + 预期（如 `npx vitest run <file>` 全绿）
6. 返回格式：落盘型固定四段：① 改动文件清单（每文件一行）② 验证（命令+通过/失败+关键行，≤5 行）③ 下游接口事实（只列签名）④ 偏差与遗留（无则"无"）。只读型分两支：结论自足（一个判断／一个位置／是否）→ 直接回传结论 + file:line/URL 证据；须读通材料才成判断 → 完整发现写进要素 2 的产物文件，回传结论 + 证据 file:line/URL + 产物路径。两型都禁贴代码全文/过程日志/摘录原文。

## 3. 长任务

- 阶段化：进度落盘到计划/状态文件，不靠对话记忆；本任务工作目录已有进度源就更新它，没有就建只追加的 `PROGRESS.md`。`HANDOFF.md` 不算进度源。
- 交接：`HANDOFF.md` 只经 handoff 技能生成，不手写也不手改。
- 交接时机：剩下的事靠已有上下文就能做完（提交、推送、开 PR、合并、在跑任务回报后收尾、等用户一句确认），不论水位都做完、不交接，水位闸门再次拦下或最后一次保活唤醒判定要交接时除外；过水位硬线后 §1 的收尾续做只覆盖这一类。仍有要读新材料、做新判断的大块工作时，过水位硬线后先生成交接、不在本会话开工（换会话要重读材料，但上下文越长判断越差），告诉用户换新会话并给一句起手指令（「读 <交接路径> 继续」）。用户要结束会话、要把任务交给别的会话，或水位闸门再次拦下、最后一次保活唤醒判定要交接时立即生成，此时不先做收尾。
- 接手：新会话读完交接，先按产物路径核对标「在跑」的项，第一条回复向用户复述 ⑤（与核对结果不符处照实说），再动手。

## 4. 交付闸门（声称完成或推送前走一次）

全套测试+lint 拿到通过证据；只改测试不改源码时，另需改前/改后覆盖行集合对比零丢失。
why 自查：feat/refactor/perf 的 commit body 记全非显然 why；本次若含塑造后续设计的决策（选型/否决方案/非显然阈值）→ 落一条 ADR（docs/adr/，不可变）。
改动影响用户看得见的产物（界面、页面、图、地图）时：截图对照受本次改动影响的状态（可派出去），逐条写用户上一轮指出的问题已修还是仍在，给用户能直接打开的预览入口（链接或一行启动命令）；没有截图证据不说完成。任何截图验证都只拍受本次改动影响的状态。
面向他人的文稿（README、简历、邮件、报告）交付前，派一个不带本轮语境的 researcher 复核，只给读者是谁、要达成什么和产物路径，回传读不懂、有歧义和多余之处；主线程改完再复核一次，至多两轮。

## 5. Git

- main 上接新任务直接 `git checkout -b`；无关新任务回 main 另拉分支。
- worktree 仅当用户明说"并行/同时/另外开一个"时用，走 EnterWorktree（禁手动 git worktree add）；worktree 内禁 npm install / cp .env* / git stash 切任务。
- 分支 `<type>/<kebab-case>`（CI 校验）；Conventional Commits；每逻辑单元一 commit；Squash merge。
- 禁止 `git add .`；开 PR 走 /write-pr。

## 6. Skill 优先级

本 playbook 的路由优先于插件 skill 的自动触发要求。
