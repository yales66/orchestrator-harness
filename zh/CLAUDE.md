# 通用规则

本文件只记录与 Claude Code 默认行为的差分；始终中文沟通。

## 密钥与凭据

- 私钥、secret 与凭据的内容一律不读：SSH 私钥、`.env*`、token、API key、连接串里的密码，不用 Read 打开，也不用 cat/head/sed/grep 查看。某个文件的读取被用户或权限拒绝后，对所有工具都算拒读，不换 shell 命令绕过。
- 不写会输出、打印、回显或写进日志这些明文的命令与脚本（`cat 私钥`、`echo $SECRET`、把连接串打到 stdout）。
- 识别或匹配密钥文件只用非敏感元数据：文件名、mtime、公钥指纹（`ssh-keygen -lf <文件>.pub`）。用 SSH key 只经手路径：`ssh -i <路径>`，由 ssh 自己读。
- 要用 secret 值时，由用户在 `! 命令` 里自行注入或在本机手动操作，我不经手明文。新接要密钥的接口时，建一个空的独立 env 文件请用户自己填，命令以 `set -a; source <文件>; set +a` 载入后运行，代码只经读取函数把值放进请求。

## 产出文稿

面向人读的文字产出（文档、报告、说明、artifact、界面文案（含写进代码或 i18n 文件的按钮、提示、报错文字）、视频文案与字幕、邮件、简历等）的起草与审改，先加载 prose-discipline skill 并按它写；会话回复与规则文件不适用。

## 改现有代码

- 动手前 git log/blame 相关行（micro-why）；repo 有 docs/adr/ 则 ls 该目录，文件名命中手上任务的读全文（macro-why）。取回了理由且与本次改动一致，就顺着改，汇报里引出处；取回的理由说明现状是有意为之而本次改动与它冲突，先问，问题里附出处；取不回理由而改动会改变那处行为时，改动是任务目标必需的，先补表征测试钉住现状再改，提交说明写明原理由未查到、可回滚，汇报里列出；不是必需的，那处不动。要动仓库里查不到来源的业务阈值时，那处不动，其余照做，汇报里单列位置与要用户回答的问题。用户本轮点名要改的那处直接改。

## 测试

- 有逻辑的新代码 test-first（tdd-watch-it-fail）；写不出"改错时会变红"的测试就不写。
- 删减/重构无测试覆盖的行为前，先补表征测试钉住现状（看它绿），改完仍绿。
- 同一套 setup 第二次出现就抽成 helper/fixture；同一断言换输入重复就 `parametrize`（带 `ids=`）。
- 开发中只跑改动相关的测试文件，不跑全套。相关按被改导出符号的引用面算：先搜出引用它的全部测试文件再跑，不按文件名相近找。

## 出处与验证

- 往设计或代码里写约束性的上限、次数、业务阈值，只取自实测、用户数据或官方出处；语言或框架的公认默认值照用，注明出处为该默认值即可。文献只给方向时不算数值的出处。必须有个值才能跑的，取一个值并标「待实测」，不写成有依据的决定。
- 自家程序的输出不默认当真值：拿它当裁判、金标准或验收依据前，讲清哪部分精确、哪部分粗糙，给出对照外部来源的校准办法，粗糙处转成可检验的项，不靠放宽容差掩盖。
- 提方案或下结论时说明是否实测过，没测的标「假设，未实测」；依赖它的审计、推广或文稿排在实测之后。

## Docker

只管本机 Docker；远程主机与演示机上的容器不在此列。

- 主线程：任务用完 Docker 就清，不问。先删本任务起的：compose 栈用起栈时同一组 `-p`/`-f` 参数跑 `down -v`，`docker run` 起的容器跑 `docker rm -f -v <容器名>`；再跑 `docker system prune -a --volumes -f && docker volume prune -a -f`，清掉其余所有没在用的镜像、容器、数据卷和构建缓存。任务开始时已在跑的栈不算本任务起的，不 down；别的会话正在跑的容器，prune 会留下。「用完」指本任务不再需要：留给用户本地验收的栈，等用户验收完再清。
- 子智能体：只删自己起的栈和容器（brief 要求留着的不删），不跑全局 prune，回报里写明删了什么、留了什么。
