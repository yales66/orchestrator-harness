# 规则文件编辑纪律

裁决标准只有一个：**运行时行为差分**——不是"像不像废话"，不是"可不可推导"。差分从**未来无本轮语境的读者**那侧量：它读到会不会改行为，不是"我作者觉得它有用"。

## 编辑前

- 列出该文件覆盖的 3-5 个典型运行场景（谁、带着什么任务、在什么时刻读到这段）。
- 目录已 git 化的（如 ~/.claude），先 `git log -p` / `git blame` 相关行，拿承重注记再动。

## 逐处改动，按场景表裁决

对每处增删，逐场景回答"改后此场景的行为变吗"：

**增**——六类不进常驻层：
① 历史理由（哪次事故、之前怎么做、谁拍的板 → 归 commit message / memory 的 Why）
② 同一纠偏的重复强调（一条干净规则，不三连）
③ 程序性内容（怎么调用、参数怎么传 → 归按需加载的 skill）
④ 环境/模型快照（会过时；确需保留则标注日期与重测条件）
⑤ 作者坐标残渣——只因本轮编辑考虑过、读者从无的被否定替代（"别再用 X／不要 X"）。诱人默认测试：新会话零语境下会不会**自己**伸手做 X？会→是读者的诱人默认，负向点名承重（如"别自己 WebSearch，直接给 researcher 子智能体"）；不会、X 只活在你刚才的思路里→残渣，砍。正向、现在式、自足地写；正向分支已穷尽决策轴时，否定即冗余。
⑥ 自指描述——文件讲自己的 scope／加载机制／是不是"唯一真源"／为什么这样组织。对运行时读者零行为差分，只服务"正在想架构的编辑者"→ 残渣，砍。
运行事实（配置状态、外部校验的存在）不算论证，且仅当它改变读者某个决策才留：`researcher 挂了 web_search→web 调研路由给它` 留（事实换了路由）；只给"已直接命令的规则"当理由的→砍（如 `autoCompact 已关` 之于「落盘」——落盘已直接命令；`本文件仅主线程加载`／`唯一真源` 亦然）。

**引用自足**——跨文件指针必须在该文件**每个加载 scope** 都解析得到。全局层（全局 skill／全局 CLAUDE）禁指向窄 scope（项目 memory／项目文件／别的项目）；要引就引**同 scope 恒在**的东西（自带 references/、全局 CLAUDE），或**活的 source-of-truth**（`--help`、配置文件本身）——引活源顺带免了 ④ 的快照过时。

**程序性规则示例驱动**——③ 落进 skill 的"怎么用"，写可照抄的调用式（命令＋占位符＋产物去向），不堆工具的内部性质/维护信息（配置怎么焊、I/O 走哪、源码在哪、怎么改）——那些逼读者从性质反推用法。测试：新会话能否直接抄命令跑通？不能就是性质汤。

**删**——豁免、分支、护栏条款看着像废话，实为承重：它们预解了与绝对规则的冲突。"可推导"≠可删——推导是每次运行重付的税。

**绝对规则需要例外时**——改写成分支（A 型：…／B 型：…），每支各自绝对；禁止"总则＋例外"结构。

## 收尾

按改动类型分支，每支各自绝对：
A 型，删减或重构既有规则条目：派一个不带本轮语境的只读 subagent 复核者，带 before/after diff，只要结论。
B 型，新建规则文件：派同样的复核者，带 AFTER 全文。
C 型，三问①答为「无场景行为变化」的措辞、格式、错字修正：不派，自己按下面三问过一遍。凡改动情态强度、条件或分支的按 A 型；一次改动混有多型时取最严的一型。

三问：① 哪些运行场景的行为变了（新建则问：哪些句子承重、缺了会漏做动作）② 按行为差分查作者残渣：有句子改变不了任何运行时读者行为吗——尤其描述文件自身 scope／机制／来历 的自指句（改不了就砍）③ 每个跨文件指针在本文件加载 scope 是否都解析得到。

提交时 commit message 写明每处增删的行为差分依据——这是未来编辑者唯一的承重注记来源。
