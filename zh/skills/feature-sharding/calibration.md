# feature-sharding 校准数据

## 预算常数

| 常数 | 当前值 |
|---|---|
| session 健康编排预算 | 25-30 万 token |
| 单轨编排开销（契约已冻结、判断已写死） | 5-6 万 / 轨道 |
| 裁决密集轨道折算 | ≥2 倍 |
| 溢出阀触发点 | 轨道预算 ×0.6（打包时按箱上限算成具体 token 数填进 LAUNCH.md 的「预算」列） |
| S 箱上限（subagent 单程） | 8 万 |
| M 箱上限（独立会话一次收口） | 25 万 |
| spike 时长 | 30-60 分钟 |
| 读集重叠合并线 | 约三成 |
| 单会话直接带的冻结轨道数 | 3-4 条 |

## 迭代乘数表

预计总消耗 ≈（启动成本 + 读集成本）× 乘数。

| 风险类别 | 乘数 |
|---|---|
| 照既有模板抄（CRUD / 相似 router / 相似组件） | ×1.5-2 |
| 新基建（repo 首个同类文件、首条同类管线） | ×3-5 |
| 含未消未知 | 不允许进箱：先 spike，或整轨道转人监督独立会话 |
