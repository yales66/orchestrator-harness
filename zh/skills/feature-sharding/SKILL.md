# Feature Sharding（大功能分片）

**角色**：你是执行规划者与编排者，不是实现者。波次模式产出 PLAN.md 并在本 session 派发 subagent；分片模式产出到「会话包 + 合流协议 + 启动清单」为止，再按 3e 以后台会话拉起各轨道（只在要用户定凭据或付费额度时先请用户批准启动清单 LAUNCH.md），之后本会话就是父会话，按 `PARENT.md` 答疑、接力、合入、换批直到收尾。轨道只用 `spawn_tracks.py` 拉起的 `claude --bg` 会话，不用 `claude -p`：`-p` 跑完即退，没有可续的会话，也没有状态钩子。

**前置**：先跑阶段 0 路由。判为主线程直接做 → 不写变更说明。其余情况（含吃不准、要先走阶段 1/2 测量的）→ 先写变更说明 `docs/changes/<change-id>/BRIEF.md`，再进阶段 1。变更说明是各轨道共享决策的唯一出处，也是主线程验收每份轨道交付时逐条对照的基准：

```markdown
# <change-id>

> 随最后一个实现 PR 合入即冻结；之后以代码与 docs/adr/ 为准。

## 目标
<一句话 + 明确不做什么>

## 验收场景
<S1、S2…：前置条件 → 操作 → 预期结果；不可协商的行为标 MUST>

## 决策
<D1、D2…：选了什么、否决了什么、为什么。要约束后续改动的决策写成 docs/adr/ 下的 ADR，这里只写该 ADR 的文件路径>
```

**预算常数**（编排预算、分箱阈值、迭代乘数）一律查同目录 `calibration.md`，不要凭感觉发明数字。

## 阶段 0：路由——不数模块，只看预算与裁决

模块数、任务条数都不代表工作量（条数齐整的轨道实际体量可差 3-9 倍）。按下表定执行模式；吃不准就先走阶段 1/2 拿到分箱再回来定——阶段 1/2 本身就是路由所需的测量：

| 判据（按序检查，先中先得） | 模式 |
|---|---|
| 全部增量的读集 + 简报一眼可见地装进主线程当前预算余量 | **主线程直接做**——退出本 skill，照 playbook §0/§2 干活 |
| 命中任意一条：①编排预算超载（轨道数 × 单轨编排开销 + 合流余量 > 健康预算，常数见 calibration.md）②裁决在环（某轨道需用户中途决策——subagent 单程无法承载，编排者代答会稀释自己的 context）③工作集连续（轨道内步骤强串行、共享"正在改的文件"记忆，接续 subagent 会重复付整个读集） | **分片模式**——全三阶段，产多会话会话包 |
| 以上都不中，但存在多个互不依赖的变更 | **波次模式**——阶段 1/2 轻走（无未知则免 spike），全部轨道落 S 箱，本 session 波次派 subagent，不产会话包 |

判为波次 / 分片模式后，主线程只编排，不动手实现——自己一实现，编排就断了。

对用户明说收益边界：分片的收益是 context 质量与墙上时钟；subagent 与多会话消耗同一账号额度，**分片不省额度**。

## 阶段 1：接缝勘察——该不该拆

### 1a. 先剔幻影工作（已实现检测）

对每个需求点判断代码库是否已实现：定位对应文件，读关键部位（函数签名 / 路由定义 / 组件 export）。已实现的从范围剔除并向用户报告；后续勘察与预算**只算增量**。

### 1b. 派 researcher 子智能体做接缝勘察（只读，只收结论 + file:line）

沿候选模块边界按清单逐类扫描：

- 共享文件（两个候选模块都要改的文件）
- 共享读集（两个候选模块都必须读通的同一批代码）
- 隐式契约：路径 / 前缀 / 任务名 / 事件名的约定，坐标系 / 单位 / 编码 / 时区的表示约定
- 需要同时知道两边才能写的测试

### 1c. 派 spike 消已知未知（每个时长见 calibration.md，一次性验证一个具体问题）

未知按藏身处清单枚举，逐类问"这里有没有没验证过的假设"：

1. 第三方库的真实行为——先查它的 issue tracker 和真实调用，不要只读官方文档
2. repo 首个同类文件（首个组件测试、首个某类管线）——隐藏的基建成本
3. 跨坐标系 / 格式 / 编码 / 单位的转换点
4. 双环境差异（多 Python 环境、worktree 与主仓的依赖差异之类）；轨道要写主仓里不进 git 的共享目录（数据、缓存）时，经符号链接从 worktree 往外写会被隔离拦下，HANDOFF 里把轨道产物定在 worktree 内被 git 忽略的目录，并按 3d 在 MERGE-PLAN.md 写拷回命令
5. 对外网络出口（默认 CDN / 字体 / 遥测请求）
6. 同机共享资源：并行轨道同时跑构建、测试、容器、模型时争的磁盘、内存与交换空间、端口、单实例锁（数据库、模拟器、GPU）——量出单轨峰值占用乘轨道数对照本机余量，超了就把重活排进不同波次，或在 HANDOFF 下游须知里写明串行用的锁

### 1d. 未知处置——三选一，然后才能继续

每个未知必须落入其一：

- **消掉**：spike 得出确定答案
- **包住**：把未知完整封进单一轨道的边界内（如"前端库只许出现在单一封装组件内"），**禁止任何未知横跨两条并行轨道**——横跨的未知一旦爆炸就是跨轨道返工，并行收益归零
- **钉死接缝**：未知天然骑在接缝上（如坐标系约定）→ 用 golden fixture 手法：造一份两侧共同断言的已知数据（已知输入 → 已知输出，含边界情形），把"共享的未知"转成"两侧各自可验的确定性"，并写守护测试防 fixture 自身退化

### 1e. 拆 / 不拆四判据（对每对相邻模块裁决）

1. **简报可压缩**：该模块开工所需的全部上下文能写成一份远小于其工作量的六要素简报（六要素定义见编排者 playbook §2）。写不紧凑 = 隐性上下文太多 → 不拆
2. **读集重叠**：两模块读集重叠超过合并线（见 calibration.md）→ 合并，或把共享阅读提前到波次 0、把结论下沉成"下游须知"
3. **飞行中零协调**：所有接缝要么已冻结、要么可打桩（对尚不存在的对侧接口用 `patch(..., create=True)` 类手法打桩，双方按冻结签名各自开工）
4. **独立可验**：每条轨道有自己的测试闸门，不依赖兄弟轨道合入

**产出**：接缝清单（耦合点 / 冻结方式 / 守护测试）+ 未知清单（每条标注处置方式）+ 文件归属表（每轨道独占写集，以整个文件为单位，互不重叠；同一文件按行段或函数分给两条轨道仍算重叠，合流时照样冲突。两轨道都要改的文件——归属一轨，或上移波次 0 预先消除，如把共享注册点做成各轨道只填充自己文件的空壳）。**闸门**：存在未处置的未知 → 不得进阶段 2。

## 阶段 2：工作量预算——拆多大

对每个候选模块测三个量，只分箱，不假装能精确预测：

| 量 | 怎么测 |
|---|---|
| 启动成本 | 简报 + 契约 + 须知实际写出来数 token |
| 读集成本 | 该模块必读文件的总量，`wc -c` 除以 ~4 估 token |
| 迭代乘数 | 查 calibration.md 乘数表（按风险类别） |

预计总消耗 ≈（启动 + 读集）× 迭代乘数，落箱（阈值见 calibration.md）：

- **S 箱** → subagent 单程可胜任。上限按"无监督可信区间"定——subagent 单程无人纠偏，跑得越久走偏越晚发现、只能整体重派——**不按 context 窗口定**
- **M 箱** → 独立会话一次能收
- **L 箱** → 必须再拆；确实拆不动 → 照独立会话拉起，启动清单「预算」列按 M 箱上限算触发点：轨道的水位钩子到线就让它交接，由父会话拉接力会话接着做（见 3e 与 PARENT.md）

分箱只认上面三个测量值——任务条数不是工作量（阶段 0 已给数据）。

## 阶段 3：拓扑路由与会话打包——在哪跑

### 3a. 拓扑决策表

| 轨道特征 | 拓扑 |
|---|---|
| S 箱，且判断已写死（契约冻结、有范本可抄、一次交付可验） | subagent——本 session 波次派发：同波 = 无共享文件、无依赖，一条消息并行发出；有依赖 → 下一波，prompt 指向前置轨道的交付产物。dispatch prompt 按六要素写全（见编排者 playbook §2），执行所需的规划都写进 prompt，subagent 不另走规划流程 |
| M 箱；或需实测 / 需人中途裁决；或工作集连续 | **独立会话**（按 3e 拉起，发会话包） |
| 契约设计、合并裁决、跨轨道取舍 | 主线程，永远不外包 |

编排容量约束（常数见 calibration.md）：本 session 直接带的 subagent 轨道数不超过单会话冻结轨道数上限（见 calibration.md），裁决密集的按 ≥2 倍折算，留合流余量。独立会话内部再派 subagents 时受同一约束：人 → 每轨道一个独立会话（编排 + 裁决）→ 各自的 subagents（执行）。

**波次模式**（阶段 0 路由来的，或阶段 2 全部轨道落 S 箱且无人裁决轨道）：不产会话包——文件归属表 + 波次划分写进 `docs/changes/<change-id>/sharding/PLAN.md`，随即按上表派发，派发时把 PLAN.md 路径告诉用户；完工后同样走「校准回填」。

### 3b. 波次 0 必含三件套（并行轨道开工前单独做完并合入：波次模式下单独派一波实现子智能体，分片模式下由一个独立会话做；契约设计本身按 3a 留在主线程，波次 0 只实现已定的设计）

1. **契约冻结**：真源 + 各镜像 + **机械化对齐测试**（解析各镜像与真源逐字段比对的测试，冻结纪律靠它执行，不靠 prose）
2. **walking skeleton**：一条 hello-world 级的最小端到端竖切，把联调期风险提前到并行开工之前暴露
3. **结论下沉**：把勘察与波次 0 实作中发现的环境坑、依赖坑、范本 file:line 写成各轨道 HANDOFF 的"下游须知"（波次模式写进各派发 prompt 的已知上下文）——每个后续波次结束时同样回填下一波（滚动规划，不一次规划到底）

### 3c. 会话包（每条独立会话轨道一份）

会话包产物（`HANDOFF-*.md`、`MERGE-PLAN.md`、`LAUNCH.md`、`PARENT.md`）写进 `docs/changes/<change-id>/sharding/`，与 BRIEF.md 及其引用的 ADR 一起提交到基线分支并推送到远端——轨道会话的 worktree 从主仓当前提交切出，开工先快进到基线分支，由此带上自己的一份；轨道的 PR 以远端基线分支为目标。REPORT 写同目录、落在各自分支上，互不冲突。

HANDOFF 只放指针与轨道特有事实：不抄变更说明（会漂移），也不抄 CLAUDE.md / playbook 管线纪律的通则（test-first、"必须过交付闸门"这条规矩本身、git 规矩）——harness 会把全局与项目规则栈自动注入每个新会话，重抄即双源。本轨道的**具体**验收命令与预期输出属轨道特有事实，仍写进「验收 + 自验」。轨道怎么回报、什么时候交接由拉起脚本接在开工句后的收尾约定规定，HANDOFF 不重写。模板（新会话只读它开工，必须自足；全部占位符打包时填实）：

```markdown
# HANDOFF-<轨道>

## 目标
<一句话任务 + "完成"的客观判定；本轨道覆盖 BRIEF.md 的验收场景 S…>

## 文件范围
独占：<精确路径>
只读参考：<路径>（冻结，不得改）
禁触：<路径>（含归属其他轨道的文件）

## 共享决策 / 接口
读 docs/changes/<change-id>/BRIEF.md 的「决策」拿共享决策；本轨道涉及的冻结签名 / 打桩方式：<列出>

## 下游须知
<波次 0 下沉的结论：环境坑、依赖入口、范本 file:line、要串行用的同机资源与锁>

## 验收 + 自验
<交付闸门命令 + 预期输出>

## 回报
交付闸门通过后写 REPORT-<轨道>.md：改动文件清单 / 验证证据（≤5 行）/
下游接口事实（只列签名）/ 偏差与遗留（无则写"无"）；然后开 PR（目标为远端 <基线分支>）
```

### 3d. 合流协议 `MERGE-PLAN.md`

- 合并顺序（依赖在前）；每条轨道的合并闸门 = 它的交付闸门 + 契约机械化对齐测试全绿。合并由父会话按此顺序逐条执行，轨道会话只开 PR
- 父会话在主仓目录工作、不进轨道 worktree，所以每条轨道写出在主仓目录就能确认合并闸门的照抄命令（如 `gh pr checks <PR>`，加上 `gh pr diff <PR>` 里 REPORT-<轨道>.md 的验证证据；REPORT 只在轨道分支上）与合入命令；另写出合流核对命令，在主仓目录 `git pull --ff-only` 之后运行。轨道产物在 worktree 内被忽略目录的，在该轨道合入命令之前写出拷回命令：源路径取 `<状态目录>/<轨道>.status.json` 的 cwd 所在 worktree 加上该目录，目标是主仓的共享目录，逐文件合并、不整目录替换（主仓那个目录可能有轨道没有的原始输入）；父会话在主仓目录用绝对路径执行它，再合入，合入后的 claude rm 会连 worktree 一起删掉
- **联调波次由全新会话接手**，不复用任何轨道的已用 context：它作为一行写进启动清单的待拉起表，由父会话拉起
- 联调发现的契约问题 → 回波次 0 重新冻结并同步全部轨道，禁止单方面改

### 3e. 启动清单与拉起

启动清单落盘为 `docs/changes/<change-id>/sharding/LAUNCH.md`。每张表首列是轨道名，首个词是与 `HANDOFF-<轨道>` 一致、各行不同的轨道代号；另有一列名恰为「预算」，填该轨道的溢出触发点（预算箱上限 × calibration.md 的溢出阀系数，算成具体数，如 `15万`），拉起脚本据此给轨道会话设水位线：到线前两成提醒、到线时水位钩子拦下要它交接。此刻就能拉起的轨道放进列名恰为「开工第一句」的表格；要等前置轨道合入的放进另一张表，「拉起条件」单独成列，开工第一句放在列名恰为「待拉起的开工第一句」的列。单元格里只写句子本身，不加代码格式。开工第一句的写法：`先运行 git merge --ff-only <基线分支>（被拒时 worktree 里还没有工作，改运行 git reset --hard <基线分支>），然后读 docs/changes/<change-id>/sharding/HANDOFF-<轨道>.md，按其执行`。有波次 0 时，它是「开工第一句」表里唯一的一行，其余轨道全部进待拉起表，拉起条件写明等哪条轨道合入；该会话的最后一步把实作中发现的坑写进每份 HANDOFF-*.md 的下游须知，随本轨道的 PR 一起提交。

把各轨道要用户提供的凭据（密钥、账号）与付费额度列出来。有这类项时，连同提供方式请用户定；定好写进相应 HANDOFF 与 PARENT.md，与会话包一起重新提交并推送，再请用户批准启动清单。没有这类项时不请批，直接拉起，汇报里给出 LAUNCH.md 的路径，用户可随时叫停。凭据由用户自己填进 env 文件，会话只以 `set -a; source <文件>; set +a` 载入后运行命令，不读、不打印。全部轨道以本会话当前的权限模式拉起：跨会话消息在两端权限模式不同类时会被扣下等审批；后台会话没人看着，非 auto/bypassPermissions 模式下会停在权限确认上（等待脚本报「卡住」，要用户 `claude attach <id>` 去批），请批或汇报里向用户说明这一点。

打包时按下面的模板写出 `docs/changes/<change-id>/sharding/PARENT.md`。它是父会话的工作协议，本会话接力出去时新父会话只读它与交接文件，所以命令要能照抄运行。打包时填实的占位符：S（本技能目录的绝对路径）、R（主仓目录的绝对路径）、基线分支、change-id、权限模式和各文件的绝对路径，命令里一律写展开后的绝对路径。`<本会话名>`、`<本会话 id>` 不填实，原样留着：哪个会话在当父会话就填它自己的——会话 id 是它 scratchpad 路径里 `scratchpad` 上一级那一段，会话名是 `claude agents --json` 里 sessionId 等于它的那一行的 name。

```markdown
# PARENT

## 身份与位置
你是 <change-id> 的父会话，在主仓目录 <R> 工作，不进轨道 worktree，不切换 <R> 的分支（它停在基线分支 <基线分支>）。
启动清单 <LAUNCH.md 绝对路径>；合流协议 <MERGE-PLAN.md 绝对路径>；变更说明 <BRIEF.md 绝对路径>；
状态目录 <R>/.claude/stages/<change-id>（tracks.json 记各轨道会话名、后台 id、预算与接力记录）；权限模式 <模式>。
<本会话名>、<本会话 id> 指你自己的：会话 id 是你 scratchpad 路径里 scratchpad 上一级那一段，会话名是 claude agents --json 里 sessionId 等于它的那一行的 name。
一条轨道的「当前后台 id」是 tracks.json 里它 relays 最后一项的 bg_id，没有 relays 时是它自己的 bg_id。

## 等待
每结束一轮之前，先运行 python3 <S>/scripts/wait_tracks.py <状态目录> --once 看首行汇总：
- 「在跑」大于 0：用 Bash 的后台运行（run_in_background）执行 python3 <S>/scripts/wait_tracks.py <状态目录>（已在跑时不另起）。
  它在有轨道停下、卡住或进程不在时退出，退出即唤醒你。
- 「在跑」为 0：不起等待，它会立即退出把你空唤醒。剩下的事都要用户定时，在本会话一次向用户汇报并停下，用户答复后接着处理；
  有轨道卡住要用户去 claude attach 处理时，汇报里请用户处理完回到本会话说一声，你再接着等。
不轮询 ListAgents，不给轨道发「做完了吗」。

## 被唤醒后，逐条处理详情行里的轨道
详情行格式是「[<归类>] <轨道> <会话名> state=<agents 状态> status=<首行声明> ctx=<上下文>｜<最后一条消息>」，按行首的归类处理；
归类为在跑的不用管。state=missing 且归类为完成的，是已合入并 rm 过的轨道，跳过。
1. 完成：按合流协议的顺序确认合并闸门后合入它的 PR；排在前面的还没合入，这条先等。合入一条后，用 --once 查出其余状态为完成、
   还没合入的轨道，按顺序接着合。每合入一条，对它的当前后台 id 运行 claude stop，再对它自己的 bg_id 与 relays 里每个 bg_id
   逐个运行 claude rm（删会话与 worktree，会话记录保留）；rm 报有未推送的提交时，确认 PR 已合入后用它给出的 --discard-unpushed 参数重跑。
2. 待答：能按变更说明的「决策」与其引用的 ADR 定的，直接用 SendMessage 按会话名回复该轨道；必须用户定的攒起来，
   在本会话一次问用户，每项写背景、编号选项各自的影响与推荐，答复后发回各轨道。轨道提出要改冻结的契约时：改动能按变更说明的
   「决策」与其引用的 ADR 推出的，自己定，按合流协议回波次 0 重新冻结，并用 SendMessage 通知全部轨道；动到变更说明的「目标」、
   标 MUST 的验收场景或 ADR 级决定的，按要用户定的事处理，并通知受影响的轨道先停下相关部分。
   SendMessage 报找不到该会话（它提问后约 1 小时没人回，进程已被停掉）时，把答复作为新消息续上该会话：
   claude --resume <status.json 里的 session_id> --bg "<答复>"
   只带这两个参数：不带别的参数时它沿用该会话存下的名字、权限模式与设置、后台 id 不变；带了参数会另起一份副本，tracks.json 对不上。
3. 交接：对它的当前后台 id 运行 claude stop，用 claude agents --json --all 确认该 id 已没有 pid（进程退出才释放 worktree），再运行
   python3 <S>/scripts/spawn_tracks.py --relay <轨道> --sentence "读 <交接文件绝对路径> 继续" --state <状态目录>
4. 卡住（多半停在权限确认上）：在本会话告诉用户运行 claude attach <当前后台 id> 去处理，同时继续处理其余轨道。
5. 未声明（停下了但首行没有状态）：读详情行判断。卡在可以直接答的事上就 SendMessage 让它继续；看不出原因就 SendMessage
   请它按收尾约定补一行状态。
6. 进程不在：有交接文件就按 3 拉接力；没有就按 3 的命令以 --sentence "读 docs/changes/<change-id>/sharding/HANDOFF-<轨道>.md，
   先用 git log 与 git status 核对本 worktree 已做到哪，接着做" 拉接力。
处理完回到「等待」。同一条轨道连续两次接力都在开工后很快又停下，按要用户定的事处理，别再拉。

## 换批
当前批的轨道全部合入后，按合流协议做合流核对，运行 git -C <R> pull --ff-only，再拉起拉起条件已满足的待拉起轨道（含联调波次）：
python3 <S>/scripts/spawn_tracks.py <LAUNCH.md 绝对路径> --repo <R> --change-id <change-id> --state <状态目录> --parent <本会话名> --parent-session <本会话 id> --permission-mode <模式> --only <轨道,…>
代号已在 tracks.json 里的一律跳过。要测试拉起机制时另开会话测，不碰在跑的轨道。

## 收尾
全部合入后：按 <S>/SKILL.md 的「校准回填」统计各轨道会话峰值 context，会话记录路径取各 <状态目录>/<轨道>.status.json 的 transcript_path；
回填 <S>/calibration.md 并提交；删掉 ~/.claude/state/sharding/parents/<本会话 id>.json；在本会话向用户汇报。

## 自身接力
水位钩子要求交接时：先用 TaskStop 停掉你在后台跑的 wait_tracks；再用 handoff 技能写交接并按它第 4 步 D 拉起接力会话。
③ 的起手写「读 <本文件绝对路径>，运行 python3 <S>/scripts/spawn_tracks.py --adopt --state <状态目录> --parent <本会话名> --parent-session <本会话 id>
（填你这个接力会话自己的名字与 id），再运行 wait_tracks.py --once 看全貌，先处理已停下而还没处理的轨道（待答未回、完成未合），再按「等待」一节做」。
```

拉起（L 为 LAUNCH.md 的绝对路径，R 为主仓目录，S 为本技能目录，命令里写展开后的绝对路径；本会话 id 是 scratchpad 路径里 `scratchpad` 上一级那一段，本会话名是 `claude agents --json` 里 sessionId 等于它的那一行的 name）：
1. 本会话主线程上下文已过 25 万 token（calibration.md 的健康编排预算下沿）时先不拉起：用 handoff 技能交接，③ 的起手写「读 <PARENT.md 绝对路径>，运行 python3 S/scripts/spawn_tracks.py L --repo R --change-id <change-id> --state R/.claude/stages/<change-id> --parent <本会话名> --parent-session <本会话 id> --permission-mode <模式>（名字与 id 填接力会话自己的），然后按 PARENT.md 做」，由接力会话以干净的上下文当父会话。
2. `python3 S/scripts/spawn_tracks.py L --repo R --change-id <change-id> --state R/.claude/stages/<change-id> --parent <本会话名> --parent-session <本会话 id> --permission-mode <模式>`。脚本对每条轨道核对后台会话真的起来了；有失败时退出码非 0 并逐条打印原因（如目录未受信任要用户在 R 里先运行一次 claude 接受信任），按原因处理后用 `--only` 补拉失败的轨道。
3. 拉起成功后按 PARENT.md 的「等待」做，向用户汇报各轨道会话名，并告诉用户可用 `claude agents` 查看、`claude attach <id>` 进入任一轨道。此后按 PARENT.md 做到收尾。

## 校准回填（每个分片功能完工后）

对每个参与会话统计峰值 context，与预估箱对比，回填 calibration.md 的数据点日志与常数。常数按日志里同类数据点重算，不以单个数据点覆盖；日志里没有数据点支撑的常数，遇到第一个实测值即替换；只用当前主力模型的数据点重算。

```bash
python3 <本技能目录绝对路径>/scripts/peak_context.py <会话记录绝对路径> [<会话记录绝对路径> …]
```

会话记录取父会话自己的，加各 `<状态目录>/<轨道>.status.json` 的 `transcript_path`（接力过的轨道，前任会话的记录按 `events.jsonl` 里的 session_id 在 `~/.claude/projects/*/<session_id>.jsonl` 找）；波次模式统计本会话与各子智能体的。路径写展开后的绝对路径：工作树隔离会拦下带 `$HOME` 的命令。

同时把"计划时没想到的坑"归类回填进阶段 1c 的未知藏身处清单（新增类别或新增实例）。
