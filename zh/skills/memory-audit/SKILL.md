# 记忆审计

## 准入判据

一条记忆值得存在，当且仅当能回答：**存在哪个未来的具体动作，因为读到它而与没读不同？** 写不出那个动作就删，写新记忆时同样先过这一问。

判死的五种情形，逐条对照：

1. 事实在仓库里当场可查（代码、git log、docs/adr、CI 配置、package.json）。
2. 规则已在 CLAUDE.md 或某个 skill 里。
3. 描述的状态已不成立（已上线、已退役、已被取代、待办已完成），且删掉不丢任何仍在约束未来动作的东西。
4. **整条**是"做过什么"的流水账（过程叙述、某天做了什么）；单句里出现会话指称不构成判死。
5. 与另一条讲同一件事。**合并判据是「会在同一时刻被读到」**，不是主题相似；同一时刻要读四条，就该是一条。

留而冗长的（超过约 3000 字符）单独给压缩目标，砍过程叙述、已结案的对比数字、已落进 ADR 的裁定，留坑与约束。

`description` 字段是用来判断相关性的，不是内容摘要；正文可写它的理由（由哪起事故或哪项裁定而来），不写指向来源会话的指称（如「本次会话」「上次对话」、会话 ID）。

## 两层体积，分开算

索引 `MEMORY.md` 每个 session 与**每个 subagent** 都要付（2026-09 实测 subagent 会加载两份 CLAUDE.md 与 MEMORY.md，与官方文档所述相反；重测法是派个 haiku 只问它上下文里有没有索引的特征串），记忆正文只在被读时付。压索引的收益乘以派发次数，压正文的收益只在命中时兑现。先压索引。

## 流程

1. **定位并备份**。记忆目录是上下文里载入 `MEMORY.md` 时标出的路径所在的目录。它通常不在任何版本控制里，删除不可回滚：
   ```
   D=<memory 目录的父目录>        # memory 的父目录
   tar -czf "$D/memory-backup-$(date +%Y%m%d-%H%M%S).tar.gz" -C "$D" memory
   ```
   备份包落在 memory 的兄弟位置，不要放进 memory 里。
2. **通读裁决**。跨条目找重复必须一次看全，不可拆分；外派时 prompt 里写死只裁决不执行、不许碰 memory 目录，产出裁决表到产物文件。
3. **抽查裁决**。凡理由是"已在仓库/已在常驻层"的，挑删除损失最大的几条实地 grep 验证，别照单执行。
4. **回读运行时**。外派 agent 只能对照仓库，验证不了线上状态；凡涉及定时器、服务、数据新鲜度的断言，ssh 或查库回读一次再定。
5. **主线程执行**删除、落盘、改名；不交 subagent。
6. **重建索引**：从各文件 frontmatter 的 `name` 与 `description` 生成，校验四项：索引指向的文件都存在、没有未被索引的孤儿文件、`name` 与文件名一致、存活记忆里的入站 `[[链接]]` 都有目标（删除与改名都会制造悬空，`name` 用连字符而文件名用下划线也会）。

## 陷阱

记忆里的标识符可能记错，按它去查会查不到而误判为"不存在"；查不到时先用模式匹配（前缀、关键词）确认真伪，再下结论。

重写后内容与文件名脱节的要改名，改前 grep 全部记忆确认无入站 `[[链接]]`。

审计 agent 给出的"该删"理由若是推断而非实证（例如"某某机制结构上已保证"），推翻它保留，除非你能指出那个机制覆盖了全部场景。
