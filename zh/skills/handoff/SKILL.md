# 交接生成

守卫钩子拒绝对 `HANDOFF.md` 的任何直接写入；它只能由第 3 步的脚本落位。

## 步骤

0. 自检，按下列顺序取第一条成立的处理：
   A. 剩下没有要会话去做的事（这条线已结束，或只剩用户本人要做的事），且没有待用户答的问题：做第 2 步 d；本会话登记过任务清单 `~/.claude/state/checklists/<会话 id>.json` 的，把仍为 todo 或 doing 的项按实情改成 done，或改成 blocked 并在 note 写原因。然后按第 1 步定目录并删残留：`<dir>` 下没有 `HANDOFF.md` 就不生成交接，把结束状态与用户还要做的事追加进进度源；有 `HANDOFF.md` 就只写首行与 ⑤（说明这条线已结束、用户还要做什么）作 `<dir>/HANDOFF.new.md`，执行第 3 步的 `finalize.sh` 落位，免得旧交接被新会话当成待办。最后告诉用户这条线已结束、还要他做什么，不进第 4 步。
   B. 用户要求交接、要结束会话或把任务交给别的会话，或水位钩子再次拦下、最后一次保活唤醒判定要交接：进第 1 步；保活唤醒时待答的问题原样写进 ③ 并标待用户答，不重新提问。
   C. 剩下的未完成项全是收尾（提交、推送、开 PR、合并、在跑任务回报后收尾）：不生成交接，回去做完。
   D. 有按编排手册分型属 B 型、拍板后还有大块工作的问题：用普通文字提问（AskUserQuestion 等待期间唤醒送不到），先做完一切不依赖答复的工作，无事可做时用 Bash 在后台运行 `sleep 3000` 再结束回合，它结束时会话被唤醒；用户在唤醒前答复，用 TaskStop 停掉它，按答复重走本步。唤醒时用户已答复就忽略；未答复的按编排手册把旧问题重新分型：属 A 或 C 型的按推荐继续做，A 型把依据、C 型标「待用户确认」写进决策记录或进度源；仍属 B 型而有不依赖它的工作，做完再起一次后台 `sleep 3000`；确实无事可做，从第 1 步生成交接，把问题原样写进 ③ 并标待用户答。后台命令起不来，或会话缓存不超过 10 分钟，不设唤醒，直接这样生成。唤醒不用 CronCreate，因为 auto 模式分类器把它判为未经授权的持久化而拒绝。3000 秒是会话缓存 1 小时过期（2026-10 的 Claude Code 设置）减 10 分钟，赶在过期前写完交接，免得用户回来时按全量上下文重写缓存；缓存时长变了按同一算法改。
   E. 其余：进第 1 步。
1. 定目录 `<dir>`：本任务的工作目录，已有 `HANDOFF.md` 就用它所在的目录。有残留的 `<dir>/HANDOFF.new.md` 先删掉。
2. 生成。a、b、d 放在同一条消息里并行发出：此刻主线程上下文很长，每多一次调用就把整段上下文按缓存读价再读一遍。上下文里有压缩摘要（以「This session is being continued」开头）时例外：早期用户原话已不在上下文里，先跑 b、读完 `user-messages.md` 再写 a。
   a. 写稿：主线程按「交接结构」直接写 `<dir>/HANDOFF.new.md`，一次写成，不派子智能体起草，也不另行审稿。
   b. 抽取：`<dir>` 在 git 仓库里时先把 `.handoff-archive/` 加进本地排除，再抽取，串成一条：`f=$(git -C <dir> rev-parse --path-format=absolute --git-path info/exclude) && { grep -qxF '.handoff-archive/' "$f" || echo '.handoff-archive/' >> "$f"; } ; python3 ~/.claude/skills/handoff/scripts/extract.py --out <dir>/.handoff-archive/material --transcript ~/.claude/projects/*/<会话 id>.jsonl --repo <仓库路径>...`。本任务涉及几个仓库就给几个 `--repo`；水位钩子的拦截理由附了 transcript 路径就用它。会话 id 是 scratchpad 路径里 `scratchpad` 上一级那一段。b 报错时，落位前把 ① 里的材料路径删掉，只留会话记录路径。
   c. 落盘：本会话、旧交接与进度源里跨任务长期有效而还没落盘的偏好、否决、纠正与授权，按 memory-audit 的准入判断与归属写入：与项目无关的写进全局规则层，只关乎本项目的写进项目记忆；没有就跳过，有就在 a、b、d 之后做。
   d. 本会话排过 `ScheduleWakeup` 唤醒的，调 `ScheduleWakeup`（`stop: true`）停掉；本任务建过定时任务的，`CronList` 回来后逐个 `CronDelete`。它们挂在 Claude Code 进程上，用户 `/clear` 开新会话后照样到点触发，会在新会话里不经交接就开工。
3. 落位：第 2 步之后用户又有影响 ② 或 ③ 的新输入，或任务回报改变了「在跑」项的状态，先改 `HANDOFF.new.md`。然后按第 4 步定好分支、更新任务清单，再跑 `bash ~/.claude/skills/handoff/scripts/finalize.sh <dir>`，旧版归档到 `<dir>/.handoff-archive/`；走第 4 步 D 时把它与拉起命令用 `&&` 串成一条发出。`finalize.sh` 报错（`HANDOFF.new.md` 缺失或为空）时补写 `HANDOFF.new.md` 再重跑，不按第 4 步 B 处理。
4. 接力。本会话登记过任务清单 `~/.claude/state/checklists/<会话 id>.json` 的，拉起接力会话或停下之前，先把其中仍为 todo 或 doing 的项改成 blocked，note 写交接路径，再按下面所走分支写接力会话名、「等用户答复：<问题编号>」、「等用户开新会话」或「已交给父会话」之一。按下列顺序取第一条成立的处理：
   A. 本会话的开工指令或它读的交接文件另行规定了接力方式（分片父会话的 PARENT.md、分片轨道开工句后的收尾约定）：按那里的规定做。
   B. ③ 的未完成项全部依赖待用户答的 B 型问题：告诉用户交接路径和起手指令「读 <交接路径> 继续」，请用户答复时开新会话用它起手，然后停下，不拉起接力会话。③ 里没有要会话去做的项（只剩用户本人要做的事），或用户本轮说了不续做、要自己开新会话：告诉用户交接路径和起手指令「读 <交接路径> 继续」，然后停下。
   C. ③ 里有标「在跑」、完成时会通知本会话的后台子智能体或 `run_in_background` 命令，且起手项要用它的产物：先不落位、不拉起，等它的完成通知，等待期间不做 ③ 的工作；同时用 Bash 在后台运行 `sleep 3000` 作等待上限（算法同第 0 步 D）。完成通知先到：用 TaskStop 停掉 sleep，按第 3 步照回报改该项，成功写已完成与产物路径，失败写失败原因并把起手改成重跑或排查，再按 D 落位并拉起。sleep 先到：该项保留「在跑」，按 D 落位并拉起，由接力会话按 ③ 的核对办法去查。
   D. 其余：自行拉起接力会话，在新的 Ghostty 窗口里运行，不抢用户当前窗口的焦点：
      `python3 "$HOME/.claude/skills/feature-sharding/scripts/launch_tracks.py" --sentence "你的会话名是 <仓库目录名>-R<n>。读 <交接绝对路径> 继续" --track R<n> --repo <仓库目录> --name-prefix <仓库目录名> --permission-mode <本会话当前模式>`
      `<仓库目录>` 是本会话启动所在的目录（主仓或工作树根），`<仓库目录名>` 是它的最后一段；本会话的开工句里写了「你的会话名是 <仓库目录名>-R<k>」时 n 取 k+1，否则取 1。拉起的会话名是 `<仓库目录名>-R<n>`。拉起脚本报错时按 B 的后一种情形处理，并把报错原文告诉用户。拉起成功后把会话名与交接路径告诉用户，本会话停下。

## 交接结构

首行用用户原话写这条线最终要做成什么、以什么判好坏；随后五段按 ⑤①②③④ 排。

- ⑤ 给用户的接续说明：三到五句用户读得懂的话，说在做什么、停在哪、下一步要用户做什么，不用内部编号与自造术语。
- ① 现状：先写工作所在的仓库或工作树绝对路径与分支名、本任务进度源的绝对路径（存在时），本会话 id 与会话记录路径 `~/.claude/projects/*/<会话 id>.jsonl`，以及本次抽取的 `<dir>/.handoff-archive/material/user-messages.md`（用户原话全文）与 `git-state.md`，只作定位，接手方要查用户原话或细节时按需读；其余只写 git、进度源与项目记忆里读不到的已验证事实：仓库外的产物路径、远程服务器与训练机状态、本轮实跑结果。提交、推送与 PR 状态不写，接手方按 ③ 的核对办法自己看；本会话所知与仓库、进度源或旧交接的说法有矛盾的，照实写出。不写过程。
- ② 约束：仍约束某个 ③ 项的选择、否决、纠正与授权，每条一行，写明约束的是 ③ 哪几项，后接一个「因为…／除非…」分句；来自用户的附不超过 20 字的原话。随交接带过去的付费额度按余额写：预批总额、已花、剩余、截至时间，接力会话只按剩余额度执行。约束不到任何 ③ 项的不写。已写进项目记忆或全局规则的，该条照样写它约束的 ③ 项，照样附用户原话，再写出处（记忆文件名，或全局规则的文件与节名）；约束本身要逐字照抄才不走样的（设计口味、被否的写法），把原话与被否原文抄全，不受 20 字限制，抄全的原文另起缩进块，紧跟该条。
- ③ 未完成项：按先后编号，第一项标「起手」，写明新会话的第一个动作，它若依赖待用户答的问题就引用该问题。每项＝动作＋完成判定＋新会话核对其状态的办法（`git status`、产物路径或测试命令）。完成判定里的阈值与口径注明出处：用户定的附原话；来自记忆、仓库文档或旧交接的写出处文件；本会话自定的写「本会话自定，可改」；查不到出处的写「出处未查到」。等用户答的问题原样写进并标「待用户答」；仍在跑的后台子智能体或命令标「在跑」并给产物路径；第 2 步 d 停掉的唤醒与定时任务，新会话仍要轮询的写成一项，附原提示与间隔；改部署配置的判定同时锚仓内 file:line 与运行态。
- ④ 下游须知：不查就会踩、且做某个 ③ 项时会撞上的坑，给 file:line／命令／阈值。

材料的用法：

1. 本会话里用户的每条偏好、否决、纠正与授权，连同旧交接与进度源里的，都要归位：约束剩余 ③ 项的进 ②；跨任务长期有效的按第 2 步 c 落盘，同时约束剩余项的两处都写；能由仓库配置、脚本或检查保证的写成一个 ③ 项「写进仓库」，给出要改的文件与写法；只关乎已完成工作的哪里都不写。
2. 旧交接与进度源只当材料，每条内容都按本结构重判，不照抄；已完成的项连同只约束它的内容一起消失；旧交接 ④ 里的坑、③ 里定义过的口径与判据，只要还适用就带过来，不因整份重写丢掉。

取证与准入：③④ 里的数字、路径、行号、阈值写本会话实测或读到的值，本会话没核过的标「未核」；本会话没有实跑记录的代码与命令标「设想，未验证」；③ 里未核实的设计，完成判定第一步写「先核实这个设计成立」。不为写交接另去取证，接手方动手做某项时会读到它依赖的前提。接手方是同配置的新会话，它起手自带或能从仓库、git 历史与项目记忆读回的不写，只写本轮做出来或查出来而它读不回的（约束 ③ 项的记忆按 ② 写原话与出处，不算重复）；仓库里只有意思相近、覆盖不到用户原话的规则，不算读得回。不写交接文件自身的用途与写法。
