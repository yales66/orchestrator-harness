# 编排者 Playbook

## 0. 主 context 只留结论

按顺序取第一条命中：
- 主线程接下来要编辑的文件 → 自己读。
- 会产出大量主线程之后不再回看的工具输出（调研/审查/抽取/诊断/草拟/反复验证/截图 QA/多轮调试/跑脚本/批处理）→ 派。
- 实现，判断已写死、六要素写得出 → 派，只回验证结论。
- 决策（选型/规划方案/设计实验/定阈值/验收/拓扑）→ 主线程。
- 其余（如已知位置的单次检索）→ 自己做。

## 1. 任务路由

| 情形 | 做法 |
|------|------|
| 明确的单模块任务 | 主线程直接执行，调研与可交接的实现按 §0 派 |
| 方向有分叉，或涉及交易/资金/删数据 | 先 AskUserQuestion 钉方向；分叉成树、互相牵连 → grilling |
| 多模块改造 / 从零建项目 / 并行意图（按接缝与预算路由，不按模块数） | 接缝与预算一眼可见、装进主线程余量 → 主线程直接规划、按 §2 并行派 subagent；其余 → feature-sharding 按预算路由（波次模式＝本 session 派 subagent；分片模式＝产多会话会话包由人拉起）→ 交付闸门 |
| bug | 先写复现测试再修（tdd-watch-it-fail）；诡异/间歇/高风险，或 2 轮修不动 → debug-root-cause。排除法定位：证实前每轮假设的取证一律派出去，主线程只留假设树与裁决；证实的那轮起，相关文件自读接手 |
| 改/设计领域模型（只读术语不算） | domain-modeling。分层：CONTEXT.md＝术语、docs/adr＝决策、memory＝跨会话笔记 |

## 2. Subagent 派发

派给谁（model 一律显式指定）：开放式全仓定位 → Explore(haiku)；纯机械批量（找文件/跑脚本/扫描）→ haiku fan-out；其余一切（只要结论的只读活如调研/审查/抽取/草拟/诊断含联网、跨文档推理、实现、判断密集）→ opus，实现走后台。

- 只读派发的交付物要有界（一个判断/命令/是否 + 证据，答到即停）；「列全/排名/每项都配」这类无停止点的穷举 → 封顶（只取最可能的一个 + 为什么）或拆发。拆发时，后步依赖前步结论的合成一发；并行的落盘型派发之间文件不得重叠。
- 落盘型派到主线程的工作区：prompt 里写死 subagent 只读 git（log/blame/show/diff/status），禁 reset／`checkout --`／restore／stash／clean／switch，禁自行提交；每轮派发结束主线程提交一次。要 subagent 自行提交则改用 `isolation:"worktree"`，主线程负责合流。

### 派发 prompt 六要素

落盘型：1–6 缺一不发。只读型：1、2、3、6 缺一不发。

1. **目标**：一句话任务 + "完成"的客观判定
2. **文件范围**：允许修改的精确路径；只读参考文件单列，标行号范围；只读派发若要求落盘完整发现，另给产物文件路径
3. **已知上下文**：已确认的结论性事实（接口签名/数据结构/坑/技术决策）写进 prompt；大块决策落盘成契约传路径；不塞文件全文，让 subagent 自己读
4. **约束**：不许动的文件与依赖、必须复用的既有模式（指向具体文件）
5. **自验**：交付前必跑的命令 + 预期（如 `npx vitest run <file>` 全绿）
6. **返回格式**：落盘型固定四段——① 改动文件清单（每文件一行）② 验证（命令+通过/失败+关键行，≤5 行）③ 下游接口事实（只列签名）④ 偏差与遗留（无则"无"）。只读型分两支：结论自足（一个判断／一个位置／是否）→ 直接回传结论 + file:line/URL 证据；须读通材料才成判断 → 完整发现写进要素 2 的产物文件，回传＝结论 + 证据 file:line/URL + 产物路径。共同：禁贴代码全文/过程日志/摘录原文。

## 3. 长任务

- 阶段化：进度落盘到计划/状态文件，不依赖对话记忆。落盘前先看同目录有无既有进度源，有则更新它。HANDOFF/PROGRESS 固定四段——① 现状（已验证的事实，不写过程）② 已定决策（后续动作会撞上的选择与否决，每条一行，不附论证）③ 未完成项（每项＝动作＋完成判定；改部署配置的判定同时锚仓内 file:line 与运行态；做完即删，结论仍约束后续则移入②）④ 下游须知（不查就会踩的坑，给 file:line／命令／阈值）。③④ 里每个数字、路径、阈值落笔前现场取回，取不回标「未核」。准入：接手方是同配置的新 session，凡它起手自带、或从仓库与 git 历史读得回来的，不写；只写本轮做出来或查出来、而它读不回来的。也不写交接文件自身的用途与写法。
- 阶段收尾时若已在重复检索早先读过的内容，把剩余阶段连六要素交接整体派发后台 agent 轻装续跑。
- 截图验证只拍受本次改动影响的状态。

## 4. 交付闸门（声称完成或推送前走一次）

全套测试+lint 拿到通过证据；改动只碰测试不碰源码时，另需改前/改后覆盖行集合对比零丢失。
why 自查：feat/refactor/perf 的 commit body 记全非显然 why；本次若含塑造后续设计的决策（选型/否决方案/非显然阈值）→ 落一条 ADR（docs/adr/，不可变）。

## 5. Git

- main 上接新任务 → `git checkout -b` 直接做；无关新任务回 main 拉新分支。
- worktree 仅当用户明说"并行/同时/另外开一个"时用，走 EnterWorktree 原生工具（禁手动 git worktree add）；worktree 内禁 npm install / cp .env* / git stash 切任务。
- 分支 `<type>/<kebab-case>`（CI 校验）；Conventional Commits；每逻辑单元一 commit；Squash merge。
- 禁止 `git add .`；开 PR 走 /write-pr。

## 6. Skill 优先级

本 playbook 的路由优先于插件 skill 的自动触发要求。
